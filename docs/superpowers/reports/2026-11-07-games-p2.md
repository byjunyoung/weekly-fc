## 3. 규칙(3D 판이 따라 할 것)

### 3.1 승부차기 `penalty2d`
- 좌표: x = 골문 따라(가운데 0), y = 골라인에서 키커 쪽(골라인 0). 골문 폭 250(기둥 반지름 6), 그물 깊이 46, 페널티 점 y=320, 키퍼 줄 y=18, 몸 반지름 22, 공 10.
- 차례: 먼저 차는 편 `config.first`(방 설정 무작위면 시작 때 rnd). k 번째 차기의 편 = (first + k) % 2. 키커 = 그 편 명단[그 편이 찬 수 % 명단 길이], 키퍼 = 상대 편 명단[같은 수 % 상대 명단 길이]. 사람 있는 편은 그 편 사람만(대기 칸은 구경), 사람 없는 편은 봇 편(차는 횟수만큼 — 고른 봇 먼저, 나머지 무작위). 혼자 = 내가 주황 편 혼자(우리 차기 전부 차고 상대 차기 전부 막음), 상대 봇 편.
- 한 차기: ready 72틱(누가 차고 누가 막나) → aim 최대 300틱(5초) → flight(판정까지, 최대 150틱) → result 100틱 → 다음 ready 또는 end.
- 키커: 킥을 이 차기 안에서 뗐다가(armed) 누르면 세기가 모인다(72틱에 가득). 모으던 걸 떼는 틱의 입력 aim 이 조준(없으면 0). 세기 p → 속도 420 + 680p, 흔들림 폭 ±(6 + 58p²) × (2 − 슈팅 배율), 슈팅 배율 = perf.kick / 평균, 0.9~1.1 로 자름. 실제 목표 = 조준 + (씨앗 −1..1) × 폭. 5초가 지나면 세기 0.15 · 조준 0 으로 자동 슛.
- 조준은 키커 화면에만: 장면(aim.ts)이 스틱으로 조준 표시를 움직이고(200/초, ±190까지 — 골문 밖도 겨눌 수 있음), 모으던 킥을 뗀 틱부터만 입력에 싣는다. 그 전 입력은 aim: null 이라 상태·채널의 in·스냅샷 inputs 어디에도 없다. 키커 화면만 조준 표시 + 지금 세기의 흔들림 폭을 그린다.
- 키퍼: y 고정, |x| ≤ 137(기둥 바로 바깥). 서서 옆걸음(최고 190 × 페이스 배율, 경기의 steer). 킥 = 몸 던지기 한 차기에 한 번(이 차기에서 뗀 적이 있어야): 그 순간 스틱 x 가 ±0.3 넘으면 그쪽, 아니면 제자리 팔 벌리기. 던짐 20틱(300/초 — 100단위) → 누움 34틱(못 움직임) → 일어나 걷기. 몸은 위에서 본 캡슐: 반 길이 서서 8 / 던짐·누움 20, 두께 12. 공이 닿으면 그 순간 "막았다". 공보다 먼저 던져도 된다.
- 판정: 공 중심이 골라인을 공 반지름만큼 넘었고 |x| < 125 → 골, 밖 → 빗나감, 기둥에 맞아 꺾였으면 골대(빗나감으로 셈), 멈추거나 150틱 → 빗나감.
- 끝: 남은 차기(정규 = kicks − 찬 수, 서든데스 = 이번 쌍에서 아직 안 찬 편 1)를 다 넣어도 못 따라잡으면 끝. 같으면 서든데스, 쌍이 끝났을 때 다르면 끝. 서든데스 20쌍이면 무승부(안전장치).
- 봇 키커(차기 씨앗 kickSeed 에서만): 기다림 20~69틱, 세기 15% 는 0.15~0.35 · 나머지 0.5~1, 조준 12% 는 ±25 · 나머지 좌우 60~105. 봇 키퍼: 조준 중엔 가운데로, 공이 나가고 18~29틱 뒤에 반응, 20% 는 공의 길을 읽고 나머지는 한쪽(±85)을 짐작 — 가까우면 걷고 멀면 던진다.
- 예측: ready→aim, aim→flight 는 넘어간다(내가 찬 공이 바로 나가 보이게), result·end 는 스냅샷만. 몸 = 공·키퍼·키커(세기 막대가 키커 몸에 있어 손님 화면에서도 바로 찬다).
- 입력 정수: x 5칸 × 킥 2 × 조준(없음 + 77칸) = 780. 킥·조준이 바뀐 입력은 급함(urgent).
- 화면: 골문이 늘 위(돌리지 않음), 위 띠 = 편마다 ● 골 / ✕ 못 넣음 / ○ 남음(폰은 최근 5개, PC 7개) + 점수 + "n번째 · 편 차례"/"서든데스" + 얼굴·이름(키커 → 키퍼, 내 것은 금색 "(나)"), 조준 중 5초 막대, 판정 띠 "골!·막았다!·빗나감·골대!", 내 차례 띠 "내가 찰 차례/내가 막을 차례", 아래 내 역할 조작 안내. 키커 고리는 모으는 중·찬 직후 하양, 키퍼는 던지는 중 하양. 소리: 조준 시작 휘슬, 킥, 던지기(tackle), 골, 막음(catch), 골대(bounce), 끝.
- 방 설정: 차는 횟수 3·5(기본 5), 먼저 차기 무작위·주황·흰. 시작 막힘: 팀 칸 사람 9명 이상, 명단이 모자라 봇 편을 못 세움.

### 3.2 자유 훈련장 `free2d`
- 시간·점수 없음, ended 늘 거짓. 방장 ✕ → 방으로, 혼자 ✕ → 나감. 단계는 늘 'play'.
- 경기장: 경기와 같은 넷(자동 = 몸 수(사람 + 봇)로 fieldFor). 벽·기둥·몸·공·킥·감쇠는 경기 값 그대로(multiball.ts). 공끼리 반발 0.7, 킥은 닿는 거리 안 가장 가까운 공 하나.
- 공 = 사람 + 2, 3~8개. 처음과 [공 모으기] 때 가운데 자리 표(보통 경기장 좌표 (0,0)(0,±56)(±56,0)(±40,±40)(0,−112), 크기 비례)에 차례대로. 골(공 중심이 골라인을 넘고 골문 안) → 그 공만 씨앗으로 고른 자리부터 다른 공·몸과 안 겹치는 첫 가운데 자리로, 속도 0. 골 수(goals)와 최근 골 4개(pops — "골!" 1초)를 상태에 둔다.
- 사람: 방 사람을 들어온 차례로 앞 8명(방장이 맨 앞 — 공 모으기 주인). 연습 봇 0~4명(기본 2)은 가까운 공 뒤로 돌아 들어가 짝수 자리는 오른쪽, 홀수 자리는 왼쪽 골대로 찬다.
- 공 모으기: 입력의 gather 비트(경기 양자화 66 × 2 = 132). config.players[i].host 인 자리의 것만 듣는다.
- 경기 중 들어온 사람: 구경(설정의 자리 수를 판 중간에 늘릴 수 없다 — 몸 목록·입력 벌 크기가 판마다 고정). 다음 시작에 들어간다.
- 화면: 경기 바닥·카메라·스틱 돌리기 그대로. 고리 = 각자 아바타 유니폼 색(너무 어두우면 밝은 중립색), 봇 회색, 내 선수 금색 화살표. 위 "자유 훈련장 · 공 n개 · 들어간 골 n", 처음 2.5초 "마음대로 차 보세요". 소리: 킥·튕김·골.
- 방 설정: 연습 봇 0~4, 경기장 자동/작게/보통/크게/아주 크게. 손님은 한 줄 요약(인원·공 수·봇·경기장).

- 혼자 승부차기(진짜 키 이벤트): → 0.4초로 조준을 옮기고 스페이스 0.5초 모아(세기 36/72) 떼면 공이 겨눈 쪽으로(vx +230, 세기 0.5) — 판정 띠까지. 키퍼 차례에 ← 로 옆걸음(x −43~−46), 공이 나간 뒤 스페이스로 왼쪽 던지기(dive −1). 끝까지 하면 결과 상자에 "패!/승!", "주황 5 : 6 흰", 선수별 "2 김준영 5/7 … 봇", "3번씩 · 서든데스 4번 · 차기 14번". 조준 표시·흔들림 폭·세기 막대·5초 막대 확인.
  - 처음 폰 화면에서 점수 띠가 ✕·♪ 에 가리고, 서든데스가 길면 편 이름이 잘리고, 아래 안내가 킥 버튼 자리와 겹쳤다 → cb8028f 에서 고침(띠를 버튼 줄 아래로, 폰은 최근 다섯, 안내를 그린 칸 바로 아래로). 고친 뒤 화면은 온라인 확인 사진(on-pen-guest-*.png)으로 봤다.
- 혼자 훈련장: 공 3개·몸 3(나 + 봇 2)·경기장 작게, 디버그 입력으로 이동(x −169 → 32), [공 모으기] 버튼 → 공 셋이 (0,0)(0,−42)(0,42). 폰 세로에서 경기장이 세워지고 "골!" 표시가 골대 앞에 뜸.
- 온라인(방장 1280 + 손님 390, 같은 크롬의 두 탭): 방장 로비의 게임 종류가 진짜 Segmented(경기·승부차기·자유 훈련장), 승부차기 설정 칸(차는 횟수·먼저 차기), 손님은 한 줄 요약("3번씩 · 무작위 · 주황 1명 대 흰 1명"). 칩으로 칸 옮기고 시작 → 3번씩 한 판 끝(주황 1 : 2 흰, 손님 "승!", 선수별 줄 양쪽 같음), 4초 뒤 둘 다 방. 손님이 키퍼인 조준 단계 화면에 조준 표시가 없음(on-pen-guest-keeper.png). 방장이 자유 훈련장으로 바꾸자 양쪽 방이 "참가" 한 칸(자동 나누기 없음, 손님 요약 "2명 · 공 4개 · 연습 봇 2명 · 경기장 자동 · 작게"). 방장 새로고침 → 방이 free2d·같은 설정으로 다시 열림. 손님은 예전처럼 방장 bye 로 "방장이 방을 닫았습니다" → 다시 들어가기. 훈련장 시작 → 손님 디버그 입력이 방장 상태에서 손님 선수를 옮김(x −56 → 190), 손님 화면엔 [공 모으기] 없음, 방장 ✕ → 멈추기 → 손님 방으로. 방장이 연 훈련장에서 [공 모으기] 버튼 → 방장 상태의 공이 바로 가운데 자리로(ui-gather.mjs).
- 같은 프로필의 두 탭은 "마지막 선수"(localStorage)를 같이 써서 방장 탭이 새로고침하면 손님 선수로 다시 연다 — 시험 환경 탓(기기가 다르면 없다), 스크립트에서 손님이 다른 선수로 다시 들어가게 했다.
- 사소한 것(고치지 않음): 손님이 방장 bye 로 입장 화면에 돌아오면 제목이 주소의 ?g=(없으면 "경기")로 보인다 — 예전부터의 흐름.

## 6. 확인 못 한 것 · 남은 것

- 실제 폰 터치(조이스틱·킥 버튼)와 소리는 못 봤다(헤드리스는 coarse 포인터가 아니다). 키보드 흐름은 진짜 키 이벤트로 확인.
- 봇 키커의 조준은 화면에 그리지 않지만, 상태의 kickSeed 와 공개된 봇 코드로 계산은 된다(봇 입력은 상태의 순수 함수라 피할 수 없다). 사람 키커의 조준은 차기 전 어디에도 없다(테스트로 확인).
- 키커가 킥을 누른 채 ready 를 넘기고 aim 에서 뗐다가 다시 누르지 않으면, 장면이 계산과 같은 규칙(armed)을 따라 해 조준을 싣지 않는다 — 다만 네트워크로 뗌이 사라지는 경우(입력은 바뀔 때만 + 0.5초 살아 있음 알림으로 다시 감)엔 계산과 장면이 잠깐 어긋날 수 있다.
- 손님 키퍼는 지연(왕복 ~150ms)만큼 늦게 본다 — 공이 나간 걸 스냅샷으로야 알기 때문(예측은 남의 입력을 모른다). 그래서 사람 키퍼는 반응보다 짐작(먼저 던지기)이 유리하다. 설계상 받아들임.
- 훈련장 경기 중 입장은 구경까지만(다음 판에 낌). 판 중간에 자리를 늘리려면 세션·예측기의 "자리 수 고정" 약속을 바꿔야 한다.
- 혼자 하기 ✕ 확인 창 문구는 공용("경기를 그만할까요? 지금까지 한 판은 저장되지 않습니다") — 훈련장에선 조금 어색하다(게임별 문구 확장은 안 함).
- 헤드리스 크롬 주의: 처음 띄운 크롬(포트 9333)을 다른 작업자도 같이 붙어 써서 탭이 사라지는 일이 있었다 — 9461 로 따로 띄워 다시 확인했다. 9333 크롬은 다른 작업자가 쓰고 있을 수 있어 끄지 않았다.
