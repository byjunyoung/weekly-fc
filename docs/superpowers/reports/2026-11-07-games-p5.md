## 3. 규칙 — 2D 와 다른 점

### 3D 승부차기
- 자리: 3D 경기장의 오른쪽 골대(x = +18, 폭 5.2 · 높이 2.1, 그물 1.4) 그대로, 점은 골라인에서 9m. 공·골대·그물·크로스바·땅 튕김은 경기 계산(`containBall`) 그대로.
- 조준은 옆(0.2m 칸 ±3.6m)과 높이(0.25m 칸 0~3m). 키커 화면에만 있고 모으던 킥을 떼는 틱의 입력에만 실린다(2D 와 같은 약속, 시험 있음). 세기 → 속도는 2D 곡선을 거리 비율로(11.8~30.9 m/s), 흔들림은 옆으로 2D 와 같은 비율, 높이로 0.6배. 조준점까지 포물선(낮게 겨누면 땅볼).
- 판정: 공 중심이 골라인을 공 반지름만큼 넘었고 골문 안 → 골, 크로스바 위·옆 → 빗나감, 기둥·크로스바를 스쳤으면 골대(들어가면 골), 키퍼 몸에 닿으면 막았다.
- 키퍼: 골라인 위 옆걸음(3.9 m/s, 페이스 ±10%). 슛 키 = 몸 던지기 한 번: 옆은 스틱 좌우, 높이는 ↑ 높이·↓ 낮게·가운데(던지는 몸 높이 0.35·0.85·1.45m), 스틱이 가운데면 제자리에서 팔 벌리고 뛰기(가운데 높은 공용). 막기 = 몸 부피(서 있으면 몸통 캡슐 + 어깨 높이 팔 캡슐, 던지면 그쪽으로 누운 몸 캡슐 하나 — 손끝 1.55m). 던짐 20틱·누움 34틱은 2D 와 같다.
- 카메라(내 결정): 키커 차례 = 공 6.2m 뒤·3m 높이에서 골대(키커 그림은 0.75m 옆으로 비켜 골문을 안 가림). 키퍼 차례 = 그물 뒤 3.4m·2.7m 높이에서 키커 쪽 — 골대 앞에서 보면 키퍼 자신이 화면을 가리고, 골대 뒤라야 공이 오는 쪽과 골문 폭이 한눈에 보여서. 화면 좌우가 경기 좌우와 반대라 조작은 화면 기준으로 뒤집어 넘긴다(← 를 누르면 화면 왼쪽으로). 구경은 키커 카메라.
- 조작: 3D 경기 키 배치 — 방향키로 겨누기(키퍼는 옆걸음), D·스페이스(폰은 슛 버튼)가 모으기/던지기. 폰은 슛 버튼 하나만 보이고 키퍼 차례엔 "던지기".
- 화면 글·소리는 2D 와 같다(띠 ●/✕/○, "n번째 · 편 차례", "키커 차기 → 키퍼 막기", 5초 막대, 골!·막았다!·빗나감·골대!, 내가 찰 차례/내가 막을 차례, 결과 상자·선수별 줄, 휘슬·킥·던지기·골·막음·골대·끝).
- 봇 키커 높이: 55% 낮게(0.15~0.65m), 35% 가운데(0.7~1.4m), 10% 높게(1.45~1.9m). 봇 키퍼: 2D 계획 그대로, 읽으면 지날 곳의 높이로 던질 높이를 고른다.

### 3D 자유 훈련장
- 공 여러 개 규칙(내 결정): 공마다 주인 하나, 한 사람은 공 하나까지. 아무도 안 가진 공은 경기의 잡기 조건(거리·높이·상대 속도) 안의 공 없는 사람 중 가장 가까운 사람이 잡는다. 차기는 내 발밑 공, 없으면 바로 앞 낮은 아무도 안 가진 공 중 가장 가까운 것(논스톱). 남의 공에 몸으로 붙으면 경기처럼 빼앗거나 흘러나온다(공마다 잠금). 공끼리 반발 0.7. 패스는 보는 쪽 가까운 아무에게나(편 없음). 슛 보정은 보는 쪽 골대 어느 쪽이든.
- 경기장 크기 고르기는 없다 — 3D 계산의 경기장이 상수(36×22m) 하나라서. 방 설정은 연습 봇 0~4 만.
- 공 모으기: 3D 경기 입력 정수 바로 다음 하나(68,640 = "가만히 + 공 모으기"). 비트로 곱하면 MAX_CODES(131072)를 넘는다. 방장 자리 것만 듣는다.
- 시점 셋(✕ 아래 버튼, [공 모으기]가 있어 한 칸 아래), 1인칭 보는 방향은 3D 경기와 같은 64방향 양자화. 위 줄 "자유 훈련장 · 공 n개 · 들어간 골 n", 처음 2.5초 "마음대로 차 보세요", 골마다 작은 "골!" 1초. 고리는 아바타 유니폼 색(봇 회색), 내 선수 금색.
- 연습 봇: 남이 안 가진 가까운 공 뒤로 돌아 들어가 몰고, 짝수 자리는 오른쪽·홀수 자리는 왼쪽 골대 13m 안에서 슛.

- 온라인(방장 1280 + 손님 390 모바일): 방장 게임 종류 Segmented(경기·승부차기·자유 훈련장), 승부차기 설정 칸, 손님 요약 "3번씩 · 흰 먼저 · 주황 1명 대 흰 1명". 시작 → 손님 키커 화면 띠 "이철후(나) 차기 → 김준영 막기", 방장(키퍼) 화면엔 조준 표시 없음, 손님 슛이 방장에서 왼쪽 위로 → 골, 손님 키퍼 옆걸음·던지기가 방장 상태에, 손님 한마디 → 방장 화면에 말풍선, 방장 ✕ 멈추기 → 손님 로비. 방장이 자유 훈련장으로 바꿈 → 양쪽 "참가" 한 칸, 손님 요약 "2명 · 공 4개 · 연습 봇 2명", 시작 → 손님 이동이 방장에, 손님 화면엔 [공 모으기] 없음, 방장 [공 모으기]. 콘솔 오류·예외 0(모든 실행).
- 3D 경기(장면 코드를 넓힌 커밋의 영향): `?g=match3d` 혼자 하기를 다시 열어 틱 진행·그리기 호출 35·이름표·점수판, goalChance → "골! 김준영 · 도움 …" 그대로, 콘솔 오류 0(`m3-solo-play-1280.png`).
- 2D 게임은 이 단계에서 화면 코드를 바꾸지 않았다(단위·빌드 테스트로만 확인).

## 6. 확인 못 한 것 · 걱정

- 실제 폰·사파리(WebKit) 손님과 실제 터치, 소리는 못 봤다(헤드리스 터치 흉내와 소스 검사 — step 에 들어가는 값은 표·곱셈·sqrt 뿐).
- 사람 둘이 아무것도 안 누르면(5초 자동 슛 = 약한 가운데 땅볼) 가운데 선 키퍼가 계속 막아 서든데스가 20쌍까지 간다(약 6분) — 2D 와 같은 규칙에서 나온다. 루프백 세션 시험은 그래서 끝까지 갈 때 봇 입력을 쓴다. 온라인 헤드리스 확인은 ✕ 멈추기로 방에 돌아왔다(결과 상자는 혼자 하기에서 봤다).
- 카메라 바로 앞 내 몸의 이름표는 뺐다(등만 보여서). 한마디 말풍선은 처음엔 같이 빠졌다가 마지막 커밋에서 다시 띄웠다 — 고친 뒤 헤드리스로 다시 보지는 않았다.
- 훈련장 봇 넷이 공을 자주 넣어(30초에 15골쯤) "골!" 이 잦다 — 작게 바꿨지만 사용자 의견을 들어 볼 곳.
- 헤드리스 스위프트셰이더에서 3D 탭 둘이면 프레임 12~16, 혼자 20~36. 실제 기기 프레임은 못 쟀다. 앞 실행의 탭이 남아 있으면 다음 실행이 느려져 실행마다 탭을 닫았다(`close-tabs.sh`).
- 병합: 다른 작업자도 `registry.ts` GAMES 줄·`views/index.ts` VIEWS 줄·CASES 줄을 고친다 — 한 줄씩 충돌, 둘 다 넣으면 된다.
