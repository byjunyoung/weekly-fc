## 2. 틀을 넓힌 것(최종 모양)

### 2.1 어댑터 — `src/lib/games/adapter.ts`(선택 멤버만 더함)

```ts
bodies?: { get(s: S): Point[]; set(s: S, bodies: Point[]): S; jump?: number; snap?: number };
pack?(s: S): Record<string, unknown>;
unpack?(packed: unknown, config: C): S | null;
```

- `jump`·`snap` = 그 게임 좌표 단위의 "섞지 않을 한 틱 이동"·"따라가지 않고 바로 맞출 보정". 없으면 2D 값(120·90). 3D 는 m 라 3·5. 몸에 `z` 가 있으면 틱 사이 섞기가 z 도 섞는다(`smooth.ts`).
- `pack`/`unpack` — 방장 `sendSnap` 이 `pack(state)` 를 보내고, 손님은 새 `readSnap(game, config, msg)`(net.ts)가 `unpack` → `acceptSnap`(okState). 지키는 선: 잃는 것 없음(`unpack(pack(s))` 가 `s` 와 같고 이어 돌린 step 도 같다 — 공통 검사 `games-adapter.test` 가 pack 있는 게임마다 본다), pack 은 객체(parseMsg 가 배열을 거름), unpack 은 던지지 않고 null.
- `net.ts MAX_CODES` 4096 → 131072(3D 입력 68,640 가지). 공통 검사의 `codes <= 4096` 도 `<= MAX_CODES` 로.

### 2.2 등록부 한 줄 — `src/lib/games/entry.ts`

```ts
botSeatTag?(room: RoomState<T>, side: 0 | 1, i: number): string | null;   // 방 봇 자리 i 의 작은 표시(3D: 첫 칸 '키퍼')
```
`Lobby` 가 `BotSlot` 의 `tag`(기본 '봇')로 넘긴다 → "키퍼 · 무작위".

### 2.3 화면 — `src/react/game/views/types.ts`(그림판을 스스로 여닫는 길)

```ts
export type SurfaceIn<C> = { root: HTMLElement; canvas: HTMLCanvasElement; layer: HTMLElement; config: C; roster: Player[]; myId: number | null; playing: boolean };
export type SurfaceFrame<S, C> = FrameIn<S, C> & { dt: number };
export type Surface<S, C, I> = {
  resize(w: number, h: number): void;
  render(f: SurfaceFrame<S, C>): void;
  readInput: (() => I) | null;
  camera(): Camera | null;
  debug?(): Record<string, unknown>;
  dispose(): void;
};
export type SurfaceKit<S, C, I> = { load(): Promise<void>; create(o: SurfaceIn<C>): Surface<S, C, I> | string };
// GameView 에 더한 것
surface?: SurfaceKit<S, C, I>;
sfx(prev: S, next: S, config?: C): Sfx[];   // config 를 더함(3D 는 골키퍼를 봐야 잡기 소리를 고른다)
```

공용 틀(`MatchFrame.usePlaySurface`)이 하는 일: `surface` 가 있으면 `load()`(그동안 "화면을 불러오는 중…" 띠) → `create()`(문자열이면 그 이유를 띠로, ✕ 로 나감) → root 의 ResizeObserver·orientationchange 로 `resize` → 루프(혼자·방장·손님 그대로)가 `scene.draw(f)` 를 부르면 `render({...f, dt})`(dt 는 틀이 잰다) → 틱마다 `readHuman = override ?? readInput()`(2D 조이스틱·킥은 달지도 보이지도 않음) → `debug()` 를 `Live.extra` 로 → 끝나면 `dispose`.
`f.state` 는 이미 틱 사이를 섞은 것(어댑터 bodies)이다 — 손님은 "예측한 몸 + 스냅샷의 점수·시계·단계". 그래서 화면은 섞기를 안 한다.
틀에 더한 것: `MatchOverlay` 의 `.game-layer`(캔버스 위 DOM 층, ✕·한마디·결과보다 아래, 누름은 통과시키고 버튼만 받음), `wait`·`fail` 띠, `Live.extra`·`Live.patch`(혼자 하기 디버그 패치), 방장 세션 `debugPatch(fn)`.
2D 경기 화면은 그대로다(`mount` 길 — 바뀐 건 빈 `.game-layer` div 하나).

**나중의 3D 미니게임이 쓰는 법**(승부차기·프리킥·훈련장):
1. `src/lib/games/<id>.ts` 어댑터 — 상태가 크면 `pack`/`unpack`(3D 경기 것처럼 키를 빼고 줄로, null → −1, 참거짓 → 비트), 몸 단위가 m 면 `bodies.jump/snap`. 입력은 `src/lib/game3d/quant.ts` 의 `encodeInput3/decodeInput3`(움직임·키 다섯·1인칭 보는 방향)를 그대로 쓰거나 그 표(`FACE64`)를 쓴다.
2. 화면 `views/<id>/index.tsx` 는 three.js 를 부르지 말고 `surface: { load: () => import('./surface…'), create }`. 장면은 `views/match3d/scene.ts`·`voxel.ts`·`view3d.ts`(카메라 셋·1인칭 탱크 조작·화살표)·`input3d.ts` 를 가져다 쓴다. 장면 위 DOM 은 `layer` 에 달고 `dispose` 에서 뗀다.
3. 말풍선은 `f.bubbles` 를 머리 위에 띄운다(`surface3d.ts` 의 이름표·말풍선 투영을 그대로 본뜨면 된다).
4. 빌드 테스트(`dist.test.mjs` "three.js 묶음은 GameApp 의 동적 import 로만")는 그림판 묶음 이름이 `surface3d.*` 하나라고 본다 — 새 그림판 묶음을 만들면 이 검사에 그 이름을 더한다.

## 3. 3D 경기의 규칙(내 결정)

- 입력 양자화: 움직임 16방향 × 세기 2 + 정지(2D 와 같은 33), 키 다섯(슛·패스·스루·로빙·질주 각 1비트 — 슛·로빙 세기는 상태가 누른 틱을 세므로 눌림만 오간다), 1인칭 보는 방향 64 + 없음. 33 × 32 × 65 = 68,640. 표는 첫 사분면 16개 상수를 90도씩 돌린 것(삼각함수 없음, −0 없음).
  1인칭이면 움직임을 보는 방향 기준으로 적는다 → 앞으로 가기가 정확히 보는 쪽(경기장 기준 16방향이면 최대 11도 어긋남). 급한 입력 = 슛·패스·스루·로빙 눌림이 바뀔 때만(돌기·질주는 간격을 지킨다).
- 1인칭: 화면 쪽 시선은 연속값(카메라가 부드럽게), 보내는 값은 표 값. 손님은 그 틱에 `encode` → 풀어 쓴 표 값으로 예측(공용 손님 세션이 원래 하는 일)이라 보낸 값 = 예측이 쓴 값. 킥오프로 돌아가면 시선을 공격 방향으로 되돌린다(상태의 보는 쪽은 1인칭 입력이 덮어썼을 수 있어 믿지 않는다).
- 방: 골키퍼는 늘 봇(편마다 첫 자리). 사람은 필드 앞줄부터. 인원 = 한 편 필드 2~4(3대3~5대5, 기본 5대5), 필드가 고른 수보다 적은 편은 봇이 채우고, 사람이 더 많은 편은 사람 수대로. 한 편 사람 5명↑·사람 9명↑·명단 모자람은 시작을 막는다. 시간 1~5분, 점수 제한 없음/1/3/5. 봇 고르기는 편마다 [골키퍼, 필드 봇…] 차례. 자동 나누기는 공용(8명 → 4·4).
- 바뀐 동작 하나: 예전 시제품은 명단이 10명이 안 되면 같은 사람을 봇으로 겹쳐 세웠다. 이제는 방 규칙과 같이 막는다(혼자 연습 칸은 못 하는 인원을 흐리게).
- 문구: 시제품 딱지 뗌(카드 꼬리표 `온라인·봇·3대3~5대5`, 넘김 페이지 제목 "3D 경기", 혼자 연습 안내). 점수판·골 문구(도움)·하얀 고리·소리·결과 말(승!/패/무승부, 구경은 "주황 승")·✕ 아래 시점 버튼·FC 식 키 안내는 그대로.

## 6. 확인 못 한 것·걱정

- 실제 폰·사파리(WebKit) 손님 — 결정성은 소스 검사와 "표 값만 step 에 들어간다"로 보장했지만 실제 iOS 기기에서 방장(크롬)과 맞춰 보진 못했다. 진짜 터치 기기의 버튼 다섯·조이스틱도 헤드리스 터치 흉내로만 봤다.
- 헤드리스 탭 셋을 한 브라우저에 띄우면 스위프트셰이더가 무거워 fps 7~8, rtt 1초까지 늘었다(실채널 노드 스크립트는 153ms). 실제 기기의 프레임은 못 쟀다.
- 1인칭으로 계속 돌면 손님 입력이 사람 둘일 때 초당 ~19건(간격 50ms 한도). 공용 규칙 안이지만 2D 보다 많다 — 한도가 빠듯해지면 보는 방향만 간격을 따로 늘리는 걸 생각할 것.
- 봇 입력이 방장에서 16방향으로 양자화돼 온라인 봇이 혼자 하기 봇보다 조금 약하다(위 표).
- 병합: 다른 작업자도 `registry.ts` 의 `GAMES` 한 줄과 `views/index.ts` 의 `VIEWS` 한 줄을 바꾸므로 그 줄이 충돌한다 — 둘 다 넣으면 된다(`[MATCH2D, MATCH3D, …]`, `{ match2d, match3d, … }`). `games-adapter.test.mjs` 는 CASES 끝에 3D 줄을 더했고 `codes <= MAX_CODES` 한 줄을 바꿨다. `games-registry.test.mjs` 의 `gamesOf('3d')` 한 줄. `bot.ts`(2D)·`game-bot.test`·supabase 는 손대지 않았다.
- 예전 `/game3d/` 탭을 열어 둔 사람은 새로고침해야 넘어간다. 시점 고르기 저장 키(`wfc:game3d:view`)는 그대로라 고른 시점이 이어진다.
- 상단 메뉴의 하위 탭: `/game/` 한 페이지라 빌드 때 2D/3D 를 가릴 수 없다(`/game/` 화면엔 하위 탭 줄이 없어 보이는 문제는 없음).

## 7. 추가(조율자 확인 뒤, 커밋 50015e4)

- "틱 0 에 멈춤"의 원인: 조율자 스크립트가 띄운 크롬은 포트 9333 을 못 잡았다(다른 작업자의 `/tmp/p2-chrome` 크롬이 이미 쓰고 있었다). 그래서 스크립트는 그 브라우저의 탭에 붙었는데, 그 탭들이 `document.hidden: true` 였다(읽기만 해서 확인). 가려지면 혼자 하기는 시계가 멈추고 방장은 판을 멈추는 게 원래 규칙(2D 와 같다)이다. 같은 c205a69 빌드와 이 브랜치 빌드를 정적 서버(python http.server)로 띄우고 보이는 탭에서 돌리면 틱이 오른다.
- 고친 실제 약점: `usePlaySurface` 효과가 명단·설정·내 자리 객체 정체성에 기대고 있었다. 이제 첫 값으로 고정한다. 여는 순서는 `src/react/game/surface-mount.ts` 로 꺼냈고 `tests/unit/game-surface-mount.test.mjs` 가 시험한다.
- `astro-island` 하이드레이션 오류(`Failed to fetch dynamically imported module …GameApp… ?astro-retry`)는 Astro 섬이 컴포넌트 묶음을 처음 받다 실패해 다시 받은 기록이다. 단일 스레드 정적 서버에 크롬 여럿이 붙었을 때 난다. 내 실행(같은 빌드, 같은 서버 방식)에서는 안 났고, 그림판 묶음(`surface3d`)이 아니라 GameApp 섬 자체의 받기라 이 작업 탓이 아니다.
