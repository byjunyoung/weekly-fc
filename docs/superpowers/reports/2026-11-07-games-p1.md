## 1. 최종 약속(원문 그대로)

### GameAdapter — `src/lib/games/adapter.ts`

```ts
export type GameAdapter<C, S, I> = {
  /** 게임 종류 — 'match2d' | 'penalty2d' | … 방 설정·start 메시지·목록 카드가 이 값으로 게임을 찾는다. */
  id: string;
  /** 첫 상태. seed 는 상태 안에 넣어 step 이 그 씨앗으로만 난수를 뽑게 한다. */
  create(config: C, seed: number): S;
  /** 한 틱. inputs[i] = i 번 자리의 입력(길이 = slots(config)). 받은 상태를 바꾸지 않고 새 상태를 돌려준다. */
  step(state: S, config: C, inputs: I[]): S;
  /** 손을 뗀 입력 — 빈자리·끊긴 손님·예측의 모자란 자리. */
  idle: I;
  /** 입력 → 정수(0 ≤ q < codes). 방장·손님이 같은 정수를 풀어 쓰게(전송·예측). */
  encode(i: I): number;
  /** 정수 → 입력. 범위 밖·정수 아님은 idle(바깥에서 온 값이라). */
  decode(q: number): I;
  /** 입력 정수의 가짓수. 메시지 검사(in·snap 의 입력)가 범위를 이 값으로 자른다. */
  codes: number;
  /** 바깥(채널)에서 온 설정의 모양 검사 — start 메시지. */
  okConfig(c: unknown): c is C;
  /** 바깥에서 온 상태의 모양 검사 — snap 메시지. config 를 받는 이유: 자리 수·id 범위처럼 설정과 맞아야 하는 것까지 본다
   *  (모양이 어긋난 상태를 예측기·그리기가 받으면 프레임마다 예외를 던진다). */
  okState(s: unknown, config: C): s is S;
  /** 지금 틱 — 스냅샷 순서(낮은 틱 버림)와 소리 비교(틱이 뒤로 가면 새 판)에 쓴다. */
  tick(s: S): number;
  /** 끝났나 — 방장은 결과를 띄우고 4초 뒤 방으로, 손님은 스냅샷의 이 값을 믿는다. */
  ended(s: S): boolean;
  /** 한 판의 입력 자리 수(선수 수). 스냅샷의 inputs 길이와 예측기의 입력 벌 크기. */
  slots(config: C): number;
  /** 그 자리를 뛰는 사람의 명단 번호(num), 봇 자리면 null. 세 군데가 이것 하나로 된다 —
   *  손님이 "내 자리"를 찾고(방장은 자리 배정을 보내지 않는다), 한마디가 진짜 그 사람 자리에서 나왔는지 보고, 사람 수로 입력 간격을 정한다. */
  slotNum(config: C, slot: number): number | null;
  /** 단계 이름(예: 킥오프·경기·골·끝). 방장은 단계가 바뀐 틱에 스냅샷을 바로 한 번 더 보내고,
   *  예측기는 단계가 바뀌는 틱에서 멈춘다 — 점수·골·끝은 스냅샷만 믿게(예측이 먼저 "골"을 띄우지 않게). */
  phase(s: S): string;
  /** 예측이 넘어가도 되는 단계 전환(from → to). 없으면 모든 전환에서 멈춘다.
   *  2D 경기의 킥오프 → 경기 중처럼 점수·시계에 영향이 없고, 얼리면 굳어 보이는 전환만 true. */
  predictsAcross?(from: string, to: string): boolean;
  /** 이 입력 변화는 간격을 기다리지 말고 바로 보낸다(예: 킥을 누르거나 뗀 순간). 없으면 모든 변화가 간격을 지킨다. */
  urgent?(prevQ: number, q: number): boolean;
  /** 봇 입력(순수). 없으면 봇·끊긴 손님 자리는 idle. */
  botInput?(state: S, config: C, slot: number): I;
  /** 그리기용 몸 목록과 그 반대(순수). 있으면 세션이 틱 사이를 섞고 스냅샷 보정을 0.1초에 걸쳐 숨기며,
   *  손님 화면은 "몸은 예측, 나머지(점수·시계·단계)는 스냅샷"으로 조립된다. 없으면 그 상태를 그대로 그린다.
   *  get 이 돌려주는 순서와 개수는 같은 판 안에서 늘 같아야 한다. */
  bodies?: { get(s: S): Point[]; set(s: S, bodies: Point[]): S };
};
```

요청안에서 더한 멤버와 이유(각 멤버 위 주석에도 있음):

| 멤버 | 왜 |
|---|---|
| `codes` | 메시지 검사(in·snap 입력)가 범위를 게임마다 자른다 |
| `slotNum(config, slot)` | 손님이 "내 자리"를 찾고, 한마디가 진짜 그 자리 사람 것인지 보고, 사람 수로 입력 간격을 정한다 — 셋을 하나로 |
| `phase(s)` | 단계가 바뀐 틱에 방장이 스냅샷을 바로 보내고, 예측기가 그 틱에서 멈춘다 |
| `predictsAcross?` | 2D 경기의 킥오프 → 경기 중은 예측이 넘어간다(예전 mayEnter 예외 — 빼면 손님이 킥오프에서 0.1초 굳는다) |
| `urgent?` | 킥을 누르거나 뗀 입력은 간격을 기다리지 않는다(예전 KICK_Q) |
| `bodies?` | 틱 사이 섞기·스냅샷 보정 숨기기·손님 화면 조립(몸은 예측, 점수·시계·단계는 스냅샷)이 게임을 모르고 돌게 |
| `okState(s, config)` | 예전 parseMsg 의 상태 검사 + 손님 snapFits(자리 수·id·lastTouch 범위)를 합침 |

결과는 따로 멤버를 두지 않았다 — 세션 view 의 `result` 가 끝난 상태 그대로이고, 화면(GameView.result)이 읽는다.

### 등록부 한 줄 — `src/lib/games/entry.ts` (등록부는 `src/lib/games/registry.ts` 의 `GAMES`)

```ts
export type GameEntry<C = any, S = any, I = any, T = any> = {
  adapter: GameAdapter<C, S, I>;
  mode: GameMode;
  /** 카드·게임 종류 칩에 쓰는 이름(예: '경기'). */
  name: string;
  /** 목록 카드의 한두 문장. */
  describe: string;
  /** 목록 카드의 작은 꼬리표. */
  tags: readonly string[];
  /** 방을 만들거나 이 게임으로 처음 바꿀 때의 설정. 방이 복사해서 쓴다(이 객체는 고치지 않는다). */
  defaultSettings: T;
  /** 채널에서 온 방 설정의 모양 검사(room 메시지 — 지금 게임 것과 saved 에 든 것 모두). */
  okSettings(v: unknown): v is T;
  /** 방장이 설정을 고칠 때(순수). 범위 밖은 자르고, 바뀐 게 없으면 cur 그대로(같은 객체 — 방이 "보낼 게 없다"를 안다). */
  applySettings(cur: T, patch: unknown): T;
  /** 시작 — 방과 명단으로 이 판의 설정을 만든다. slots[i] = i 번 자리를 조종하는 clientId(봇이면 null).
   *  못 만들면 RangeError(startBlock 이 미리 막는 경우). 난수는 rnd 로만. */
  buildConfig(room: RoomState<T>, roster: Player[], rnd: () => number): { config: C; slots: (string | null)[] };
  /** [시작] 을 막는 이유(화면 문구). 없으면 null. 없는 게임은 늘 시작할 수 있다. */
  startBlock?(room: RoomState<T>, roster: Player[]): string | null;
  /** 방 화면의 팀 칸에 흐리게 보일 봇 자리 수(편마다). 편이 없는 게임은 두지 않는다(봇 칸을 안 그린다). */
  botSeats?(room: RoomState<T>): [number, number];
};

/** id → 등록된 게임(없으면 undefined). 세션·메시지 검사는 이 함수만 받는다. */
export type GameLookup = (id: string) => GameEntry | undefined;
```

방: `RoomState = { …, game, settings(지금 게임의 설정), saved(다른 게임들의 설정) }`. 게임을 바꾸면 지금 설정이 saved 로 가고 돌아오면 꺼낸다
(요청안의 `settings.game` 대신 `room.game` + "지금 게임의 설정" — 각 게임의 설정 타입이 그대로 `room.settings` 라 읽는 쪽이 한 번 더 찾지 않는다).

### GameView — `src/react/game/views/types.ts`

```ts
export type FrameIn<S, C> = { state: S; config: C; myId: number | null; bubbles: { id: number; text: string }[] };

/** 한 판 동안 열려 있는 그림판. 캔버스를 받아 2D 캔버스든 WebGL 이든 장면이 스스로 연다(getContext 를 장면이 정한다). */
export type Scene<S, C, I> = {
  /** 한 프레임. 점수판·안내 같은 캔버스 위 HUD 도 여기서 그린다. 크기가 아직 안 잡혔으면 그냥 돌아간다. */
  draw(f: FrameIn<S, C>): void;

  toInput(h: ScreenInput): I;

  camera(): Camera | null;
  dispose(): void;
};

/** 결과 상자 — outcome 큰 글자, tone 색, score 점수 줄, sub 작은 설명. 버튼은 공용 틀이 붙인다(혼자·방장·손님마다). */
export type ResultView = { outcome: string; tone: 'win' | 'lose' | 'draw'; score: ReactNode; sub: string };

/** 혼자 하기의 한 판 — 다시 하기는 make 를 한 번 더 부른다(새 씨앗). */
export type SoloSetup<C> = { config: C; seed: number; myId: number };

export type SettingsProps<T> = {

  players: Player[];

  /** 방장이면 설정 고치기, 손님이면 null(보기만 — 한 줄 요약). */
  onChange: ((patch: Partial<T>) => void) | null;
  /** 설정 줄 맨 앞에 끼울 줄(방장의 게임 종류 고르기). */
  lead?: ReactNode;

export type SoloProps<C> = {
  /** 혼자 연습 칸이 열렸나. 닫혀도 컴포넌트는 남아 고른 값을 기억한다. */
  open: boolean;

  cardRef: RefObject<HTMLDivElement | null>;

  num: number | null;
  onStart(make: () => SoloSetup<C>): void;

export type GameView<C, S, I, T> = {
  /** 등록부(src/lib/games/registry)의 같은 id. */
  id: string;
  /** 경기 화면을 연다. 못 열면(캔버스 문맥 없음) null. */
  mount(o: { root: HTMLElement; canvas: HTMLCanvasElement; config: C; roster: Player[] }): Scene<S, C, I> | null;

  sfx(prev: S, next: S): Sfx[];

  result(final: S, config: C, o: { myId: number | null; solo: boolean }): ResultView;
  /** 입장 화면 글 — sub = 제목 옆 작은 글, header = 선수 고르기 위 한 줄. */
  entry: { sub: string; header: string };
  /** 명단이 이만큼은 있어야 판을 만든다(방 만들기·혼자 연습). */
  minRoster: number;
  /** 방 화면의 설정 칸 — 방장은 고르기, 손님은 한 줄 요약. */
  Settings: ComponentType<SettingsProps<T>>;
  /** 방 화면 설정 칸 아래 안내(방장에게만) — 없으면 안 그린다. */

  controls: string;
  /** 입장 화면의 혼자 연습 칸. */
  Solo: ComponentType<SoloProps<C>>;
};
```

## 2. 게임 하나 더하기

1. `src/lib/games/<id>.ts` — 어댑터(순수: 삼각함수·시계·난수 함수 금지, 상태·설정 JSON) + 등록부 한 줄(`GameEntry`: mode·이름·설명·꼬리표·기본 설정·okSettings·applySettings·buildConfig·startBlock?·botSeats?).
2. `src/lib/games/registry.ts` 의 `GAMES` 에 한 줄.
3. `src/react/game/views/<id>/` — GameView(mount·sfx·result·entry 글·minRoster·Settings·Solo·controls·hostHint?), `src/react/game/views/index.ts` 의 `VIEWS` 에 한 줄.
4. `tests/unit/games-adapter.test.mjs` 의 `CASES` 에 한 줄(설정 몇 개, 짧은 판, 그 게임만의 망가뜨리기) — "등록된 게임은 모두 이 검사를 받는다" 테스트가 빠뜨리면 실패한다.
5. 저절로 되는 것: 그 모드의 목록 카드(`/game/?g=<id>`), 방의 게임 종류 고르기(같은 모드에 둘 이상이면 Segmented), room·start 메시지 검사, 방장·손님 세션·예측·스냅샷·메시지 아끼기, 경기 화면 틀(✕·♪·한마디·구경·띠·결과), 혼자 하기 루프, 디버그 훅(`?debug=1`).

## 6. 확인 못 한 것·남은 것

- 예전 탭(이 배포 전 페이지를 열어 둔 사람)은 새 start(game 포함)를 못 읽고, 새 탭은 예전 방장의 room(game·saved 없음)을 못 읽는다 — 배포 직후 열린 방은 새로고침해야 한다(받아들인 끊김).
- 방장이 새로고침하면 방을 다시 열 때 게임이 주소의 ?g=(없으면 기본)로, 설정이 그 게임의 기본값으로 돌아간다. 설정이 돌아가는 건 예전에도 그랬지만(createRoom 이 기본 설정), 게임이 돌아가는 건 새 일이다 — 2D 게임이 둘 이상이 되면 체감된다(sessionStorage 에 방 게임을 같이 적어 두면 된다).
- 터치 기기에서의 조이스틱·킥 버튼, 실제 폰 두 대 — 헤드리스는 coarse 포인터가 아니라 못 봤다(코드 경로는 예전과 같은 attachInput).
- 소리는 들어 보지 못했다(sfx 는 같은 detectSfx 를 같은 시점에 부른다).
- 같은 모드에 게임이 둘 이상일 때의 게임 종류 Segmented 는 화면에서 못 봤다(지금 2D 는 하나). 세션의 setGame 은 가짜 게임 둘로 테스트했다.
- 병합 주의(작업 중 origin/main 이 faa9edd 로 나아감 — 3D 효과음): `git merge-tree` 로 보면 충돌은 하나, `views/match2d/sfx-detect.ts`(main 이 옛 sfx-detect.ts 의 Sfx 종류에 shot·catch·tackle 을 더함, 이 브랜치는 Sfx 타입을 `src/react/game/sfx.ts` 로 옮김). 풀기: sfx.ts 의 Sfx 종류에 `'shot' | 'catch' | 'tackle'` 을 더하고 sfx-detect.ts 는 이 브랜치 쪽(import type)으로. 또 main 의 `src/react/game3d/sfx3d.ts` 가 `../game/sfx-detect.ts` 에서 Sfx 를 가져오므로, 3D 담당이 `../game/sfx` 로 바꾸거나 `src/react/game/sfx-detect.ts` 에 `export type { Sfx } from './sfx';` 한 줄짜리 다리를 둔다(3D 파일은 이 작업 범위 밖이라 손대지 않았다).
- 3D(`/game3d/`)는 손대지 않았다 — 4단계에서 어댑터로 옮기면 3D 목록의 손으로 쓴 카드를 지운다.
