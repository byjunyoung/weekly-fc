# 등번호 각자 고르기 · 티어로 뺏기(2026-11-06)

> 사용자: "등번호는 1-99 각자가 선택할 수 있게 기능으로 만들되, 이미 차지한 번호면 티어가 높으면 뺏을 수 있게 시스템화하면 좋을듯.
> 등번호 설정도 라커룸에서 제공하든지 하면 되고."
> 사용자 결정(셋 다 선택지로 물음): 뺏긴 사람은 **서로 맞바꿈** / 기준은 **등급이 한 칸 이상 높을 때** / 횟수·보호 기간 **제한 없음**.

## 1. 핵심 결정 — 번호(num)와 등번호(jersey)를 나눈다 (내 결정)

지금까지 `players.num` 은 선수의 고유 번호이면서 등번호였다. 계정 연결(members)·대결(votes)·능력치 기록(stat_log)·
배치(placements)·방문(visits)·매치 라인업(jsonb)·주소(`/squad/N/`)가 전부 num 에 묶여 있다. 2026-09-26 전면 재배정 때
이걸 한 트랜잭션으로 다 옮겼는데, 누구나 아무 때나 누르는 기능으로 그걸 되풀이하면 위험하다(다른 사람 화면에 남은 옛 번호로
대결 판정이 엉뚱한 선수에게 들어갈 수 있다).

그래서 **화면에 찍히는 번호만 `players.jersey` 로 따로 둔다.** num 은 그대로 고유 번호다. 뺏기 = 두 사람의 jersey 맞바꿈.

- 눈에 보이는 부작용 하나: 주소는 `/squad/{num}/` 그대로라, 번호를 바꾼 사람은 주소의 숫자와 등번호가 달라진다.
- 처음엔 모두 jersey = num.

## 2. 규칙

- 등번호는 1~99, 한 번호에 한 사람. (2026-09-26 "1번은 GK 자리로 비움" 은 사용자의 "1-99 각자가 선택" 으로 덧씌운다 — 1번도 고를 수 있다.)
- 로그인해 이름을 고른 팀원만 자기 등번호를 바꾼다.
- 빈 번호 → 그대로 갖는다.
- 주인이 있는 번호 → **내 종합 티어(S>A>B>C>D)가 주인보다 한 칸 이상 높을 때** 서로 맞바꾼다. 같은 등급은 못 뺏는다.
- 배치 전(능력치 전부 0) 선수: 빈 번호만 고를 수 있다. 배치 전 선수가 쓰는 번호는 티어가 있는 누구나 가져갈 수 있다(내 결정).
- 횟수 제한·보호 기간 없음(사용자 결정).
- 관리자는 티어와 무관하게 누구의 등번호든 정한다(주인이 있으면 맞바꿈).
- 티어는 종합 기준 — 화면의 `tierRows(players, 'ovr')` 와 서버 `private.tier_idx()` 가 같은 규칙.

## 3. 서버 (`supabase/migrations/20261106000000_jersey.sql`, 2026-11-06 실서버 적용)

- `players.jersey int not null`, 1~99, 유일(맞바꿈이 한 문장이라 deferrable).
- 넣을 때 jersey 가 비면 num 과 같은 번호(비어 있으면) 아니면 남은 가장 작은 번호(트리거).
- `private.upsert_player` — 새 선수는 payload 의 `jersey` 를 받는다(쓰는 번호면 거절). 고칠 때는 jersey 를 건드리지 않는다.
- `private.tier_idx()` → (num, tier 1~5).
- `public.pick_jersey(p_jersey int, p_num int default null)` → `{ok, jersey, swapped}`(swapped = 맞바꾼 상대 이름 또는 null).
  거절 문구는 서버가 한국어로 만든다(예: "김현서 님(S)이 쓰는 번호입니다 — 내 티어(A)가 더 높아야 가져올 수 있습니다").
- `public.jersey_log` — 누가 언제 무엇으로 바꿨나(표는 막음).
- `get_all` 은 `to_jsonb(players)` 라 jersey 가 저절로 실린다.
- 확인: 서버·화면 티어 36명 전원 일치. 되돌려지는 시험 15건 통과(로그인·이름 고르기 관문, 범위, 빈 번호, 뺏기 성공, 같은 등급·높은 등급
  거절, 배치 전 양방향, 관리자, 선수 추가, 겹침 없음).

## 4. 화면

- `Player.jersey`. **사람에게 번호로 보이는 자리는 전부 jersey** — 선수 카드·표의 # 열(정렬 포함)·선수 상세·이름 고르기 목록·
  라커룸·공유 이미지(선수 카드·단체 사진·팀 나누기·티어표)·매치 화면. 고유 번호 num 은 주소·키·서버 호출에만 쓴다.
- **라커룸 「내 선수」 칸에 [등번호 바꾸기]** → 1~99 격자 창. 칸 상태 넷: 내 번호 / 빈 번호 / 가져올 수 있음(주인 이름·등급) /
  못 가져옴(주인 이름·등급, 흐리게). 주인 있는 번호를 고르면 "○○ 님과 번호를 맞바꿉니다" 확인 뒤 실행. 끝나면 데이터 새로고침.
- 관리자: 선수 편집에서 등번호 = 같은 격자(티어 조건 없음). 고유 번호는 더 이상 손으로 고치지 않는다.
- 관리자 [선수 추가]: 격자는 등번호를 고른다. 고유 번호는 남는 가장 작은 번호로 자동.
- 순수 로직은 `src/lib/jersey.ts` 에 두고 단위 테스트(서버 규칙과 같은 판정).
