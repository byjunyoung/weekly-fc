# 3D 축구 시제품(2026-11-07)

> 사용자: "3차원 피파 같은 게임으로 만들긴 좀 그런가?" → 세 갈래(A 지금 게임에 3D 옷 / B 단순한 3D 아케이드 축구 / C 본격 축구) 중
> "b 쪽도 시도해보고 싶은데". 선택지로 물어 정한 것: **내 선수 하나만 조종**, **우리 도트 아바타를 입체로**, **달리기 · 패스 · 슛**.
> 이건 **시제품**이다 — 손맛이 재미있는지 보려는 것. 버려도 되고, 2D 게임(`/game/`)은 그대로 둔다.

## 1. 무엇인가

- 3D 로 보이는 5대5 아케이드 축구. 한 사람은 자기 선수 하나만 움직인다(나머지는 봇). 한 편 = 필드 4 + 골키퍼 1.
- 기존 축구 게임을 본뜨지 않는다 — 이름·화면 구성·선수 모델·동작을 가져오지 않고, 우리 멤버 도트 아바타와 우리 식 화면으로 새로 짠다.
- 규칙은 아케이드: 오프사이드·파울·스로인·코너킥 없음. 공은 경기장 둘레 낮은 벽에 튕긴다(높이 뜬 공은 벽을 넘지 않게 보이지 않는 천장·옆벽으로 가둔다).
  골은 골대 안(폭·높이)으로 들어가야 한다 — 크로스바 위로 뜬 공은 골이 아니다.

## 2. 내가 정한 것

- **혼자 + 봇 먼저.** 온라인은 재미가 확인된 뒤. 다만 경기 계산은 2D 때처럼 화면을 모르는 순수 코드로 둔다(나중에 방장 기기가 그대로 돌릴 수 있게).
- **주소 `/game3d/`, 상단 메뉴에 넣지 않는다.** 주소로만 들어온다.
- **three.js** 를 쓴다. 그 페이지에서만 불러온다(포털 다른 화면의 무게는 그대로).
- 폰과 PC 둘 다. 60프레임을 목표로 하되 폰에서 무거우면 그림자·효과부터 뺀다.

## 3. 조작과 동작

- 이동: PC 방향키·WASD / 폰 왼쪽 조이스틱. 화면 기준 방향.
- **패스**(PC `X` 또는 `Shift` / 폰 버튼): 짧게 누르면 보는 방향 가까운 동료에게 땅볼. 동료가 그 방향에 없으면 보는 방향으로.
- **슛**(PC `스페이스` / 폰 버튼): 누르고 있는 동안 세기가 차고(게이지), 떼면 나간다. 세게 찰수록 공이 뜬다.
- 드리블: 공 가까이 가면 공이 발 앞에 붙어 따라온다(달리면 조금 앞서 구른다). 방향을 급히 틀면 공이 떨어질 수 있다.
- 빼앗기: 공 가진 선수에게 몸으로 부딪치면 공이 흘러나오거나 넘어온다. 별도 태클 버튼은 없다.
- 능력치: 2D 와 같은 방식으로 살짝(±10%) — 페이스 → 속도, 드리블 → 공 간수, 슈팅 → 슛 세기, 패스 → 패스 정확도, 수비 → 빼앗기, 피지컬 → 몸싸움.

## 4. 화면

- 선수: 포털 도트 아바타(`avatarPixels`)를 픽셀마다 블록으로 세운 입체. 멤버마다 얼굴·머리·유니폼이 그대로 보인다.
  동작은 단순하게 — 달리면 통통 튀고 다리 블록이 번갈아 움직이는 정도, 찰 때 살짝 기운다.
  발밑에 팀 색 고리, 내 선수는 표시, 머리 위 이름표.
- 경기장: 잔디 줄무늬, 선, 골대와 그물, 둘레 낮은 벽. 포털의 어두운 도트 분위기.
- 카메라: 가로 화면·PC 는 옆에서 비스듬히 내려다보며 공을 따라간다. 세로 화면은 우리 진영 뒤에서 상대 골대 쪽으로 내려다본다(내 편이 위로 공격).
- HUD: 점수, 남은 시간, 슛 세기 게이지, 골 문구. 끝 화면(다시 하기).
- 시작 화면: 내 선수 고르기(2D 것과 같은 방식), 시간(1~5분), [시작].

## 5. 구조

```
src/lib/game3d/sim.ts     경기 상태와 한 틱(순수). 선수는 바닥 위 원, 공은 높이·중력·튕김이 있는 구. 공 소유·패스·슛·골키퍼 규칙
src/lib/game3d/bot.ts     봇 입력(순수) — 필드 봇(자리 지키기·공 쫓기·패스·슛)과 골키퍼
src/lib/game3d/stats.ts   능력치 → 성능
src/react/game3d/*        three.js 장면·카메라·입력·화면
src/pages/game3d/index.astro
```

- 2D 의 규칙 그대로: 계산 안에 DOM·시계·`Math.random`·삼각함수 호출 금지(방향은 벡터로), 상태는 JSON.
- `?debug=1` 이면 `window.__wfc3d = { getState, getConfig, setInput }`.

## 6. 확인

- 단위: 결정성, 공의 중력·튕김, 골 판정(폭·높이), 드리블로 공이 따라옴, 패스가 동료 쪽으로 감, 슛 세기와 뜨는 높이, 빼앗기, 골키퍼가 정면 공을 막음, 봇끼리 경기에서 골과 패스가 실제로 나옴.
- 화면: 폰 세로·가로, PC 에서 장면이 그려지고(빈 화면 아님) 조작으로 선수가 움직이고 차짐, 콘솔 오류 없음, 프레임 시간.
- 사용자가 볼 것: 달리는 느낌, 드리블이 붙는 느낌, 패스가 원하는 데로 가는지, 슛 게이지, 카메라, 입체 아바타가 알아볼 만한지 — 그리고 2D 보다 재미있는지.
