# 게임 묶음 기획 — 미니게임 넷 × 2D·3D × 온라인(2026-11-07)

> 사용자: "게임 메뉴는 아래 게임 여러개 고를 수 있게 만들고 만든 게임은 거기에 하나씩 추가하자", "승부차기, 프리킥, 훈련장 이런거 미니게임으로",
> "그냥 모드를 2d 모드, 3d 모드로 정의하고", "여러 게임 형태를 제공하면 될듯",
> **"자유 훈련장, 여러 드리블 훈련장, 승부차기, 프리킥 같은 게임 만들어서 온라인 가능하게 하자. 다 2d, 3d 모드 별로 가능하게 하고. 이거 알아서 기획해서 완성해놔"**.
> 그래서 이 문서의 세부는 전부 내 결정이다. 사용자가 정한 것은 위 문장들뿐이다.

## 1. 완성의 모습

```
게임 (메뉴)
  [2D 모드 | 3D 모드]
  모드마다 카드 다섯:  경기 · 승부차기 · 프리킥 · 자유 훈련장 · 드리블 훈련장
       → 오락실식 선수 선택 → [방 만들기] / [혼자 하기]
       → 방(로비): 방장이 게임 종류와 설정을 고르고 시작, 끝나면 방으로 돌아와 다른 게임으로 바꿀 수 있다
```

- 열 가지(게임 다섯 × 모드 둘) 모두 혼자서도, 방을 만들어 팀원과도 된다.
- 한 방에서 게임 종류를 바꿔 가며 논다 — 초대 링크는 하나.
- 사람은 한 판에 8명까지(실시간 채널 한도, `2026-11-07-game-fields-teams-design.md` §0). 나머지는 구경.
- 기록은 서버에 남기지 않는다(방 안 순위만). 드리블 최고 기록만 기기에 저장. 전적·랭킹은 범위 밖.

## 2. 토대 — 게임 하나 = 계산 + 그리기 + 조작, 온라인은 공용

지금 온라인 세션(방장 계산·스냅샷·손님 예측)은 2D 경기의 타입에 묶여 있다. 게임이 열 개가 되면 세션을 열 번 짤 수 없다.

```ts
// src/lib/games/adapter.ts — 모든 게임이 지키는 약속(순수)
export type GameAdapter<C, S, I> = {
  id: string;                                   // 'match2d' | 'penalty2d' | … | 'dribble3d'
  create(config: C, seed: number): S;
  step(state: S, config: C, inputs: I[]): S;    // 순수·결정적. 삼각함수·시계·난수 금지(씨앗은 상태 안)
  idle: I;
  encode(i: I): number; decode(q: number): I;   // 입력 양자화(전송·예측이 같은 값을 쓰게)
  ok(state: unknown, config: C): state is S;    // 바깥에서 온 상태의 모양 검사
  ended(state: S): boolean;
  tick(state: S): number;
};
```

- 방장·손님 세션, 예측기, 메시지 검사는 어댑터만 보고 돈다. 2D 경기를 첫 어댑터로 옮기고(동작 변화 없음), 3D 경기가 둘째 — 이걸로 **3D 경기도 온라인**이 된다.
- 방 설정에 `game`(게임 종류)과 게임별 설정이 들어간다. `buildMatch` 는 게임마다의 `buildConfig(room, roster, rnd)` 로.
- 화면은 게임마다 `{ render, input, hud }` 를 낸다. 경기 화면 틀(전체 화면 오버레이·✕·소리·한마디·끊김 안내·결과)은 공용.
- 봇: 게임마다 `botInput(state, config, id)`(순수).

## 3. 게임별 규칙

공통: 선수 능력치는 살짝(±10%). 빈자리는 봇. 조작은 그 모드의 경기와 같은 손(2D: 이동 + 킥 / 3D: 이동 + 패스·슛 등).

### 3.1 승부차기
- 두 편이 번갈아 5번씩. 동점이면 한 번씩 더(서든데스). 한 편의 사람들이 순서대로 차고, 상대 편 사람이 순서대로 막는다. 사람이 없으면 봇.
- 키커: 방향을 겨누고(스틱), 킥을 누르고 있으면 세기가 찬다 — 떼면 나간다. 세기가 높을수록 빠르지만 겨눈 데서 더 벗어난다(능력치 슈팅이 흔들림을 줄인다).
  5초 안에 안 차면 약한 슛이 나간다.
- 키퍼: 골라인 위에서 좌우로 움직인다. 공이 나간 뒤에만 크게 몸을 던질 수 있다(먼저 움직이면 반대쪽이 빈다).
- 2D: 위에서 본 골문 앞. 3D: 키커 뒤에서 골대를 보는 화면(키퍼 차례엔 골대 뒤에서), 공이 뜬다 — 크로스바 위는 노골.
- 끝: 승패와 각자 성공 수.

### 3.2 프리킥
- 정해진 자리 다섯 곳(가까운 정면 → 먼 측면)에서 한 번씩, 수비벽(봇 3명)과 골키퍼(봇)를 상대로. 넣으면 자리마다 점수(먼 자리일수록 높다).
- 온라인: 방 사람들이 차례로 같은 자리에서 차고 점수를 겨룬다. 다른 사람은 구경. (사람 키퍼 옵션은 다음.)
- 2D: 공은 땅으로만 가므로 벽 옆으로 감아 넣는 각을 찾는 게임 — 킥 직전 스틱 방향으로 살짝 휘는 "감아차기" 한 가지를 준다.
  3D: 벽을 넘기는 높이와 세기 조절이 핵심.

### 3.3 자유 훈련장
- 시간·점수 없음. 경기장에 공 여러 개(사람 수 + 2), 골대 둘. 골이 들어가면 그 공만 가운데로 돌아온다.
- 방 사람 모두가 편 없이 들어와 논다. 봇 수(0~4, 공을 쫓고 차는 연습 상대)와 경기장 크기를 고른다. [공 모으기] 버튼.
- 3D: 같은 내용 + 1인칭 시점 연습에 좋다.

### 3.4 드리블 훈련장 (코스 넷)
- 콘과 문(두 콘 사이)을 순서대로 통과해 결승선까지 공을 몰고 가는 기록 경기. 문을 건너뛰면 그 문으로 돌아가야 한다. 콘을 치면 1초 가산.
- 코스: ① 지그재그 ② 8자 ③ 좁은 문 ④ 왕복 달리기(가서 돌아오기). 코스마다 금·은·동 기준 시간.
- 온라인: 방 사람들이 나란한 레인에서 **동시에** 달린다(레인끼리는 부딪치지 않는다). 순위와 기록 표시. 혼자면 내 최고 기록(기기 저장)과 겨룬다.
- 2D: 위에서 본 코스. 3D: 뒤에서 따라가는 화면.

### 3.5 경기
- 2D: 지금 것. 3D: 지금 시제품을 온라인으로(방·팀 나누기는 2D 방과 같은 화면) — 시제품 딱지를 뗀다.

## 4. 순서 — 한 단계씩 확인하고 배포한다

| 단계 | 내용 | 끝났다고 볼 것 |
|---|---|---|
| 0 (진행 중) | 2D 봇의 패스·슛·움직임 / 3D 시제품 다듬기(1인칭, 키 배치, 골 빈도) / 오락실식 선수 선택 | 각각 테스트·화면 확인 뒤 배포 |
| 1 | 토대: 어댑터 + 공용 세션 + 방의 게임 종류 + 목록 카드. 2D 경기를 어댑터로 옮김 | 2D 경기가 전과 똑같이 됨(두 브라우저), 테스트 통과 |
| 2 | 2D 승부차기 · 2D 자유 훈련장 | 혼자·온라인 모두, 두 브라우저 확인 |
| 3 | 2D 프리킥 · 2D 드리블 훈련장(코스 넷) | 〃 |
| 4 | 3D 경기 온라인(어댑터) + 3D 선수 선택 화면 공용화 | 두 브라우저로 3D 한 판 |
| 5 | 3D 승부차기 · 3D 프리킥 | 〃 |
| 6 | 3D 자유 훈련장 · 3D 드리블 훈련장 | 〃 |
| 7 | 전체 리뷰, 폰·PC 화면 일괄 점검, 문구·간격 정리 | 열 가지가 목록에서 다 열리고 끝까지 됨 |

- 단계마다 구현자 → 리뷰 → 내가 두 헤드리스 브라우저로 실제 확인 → 배포. 깨진 채로 다음 단계에 가지 않는다.
- 사용자의 조작감·화면 의견은 단계 사이에 끼워 반영한다.

## 5. 지키는 선

- 기존 게임의 이름·화면·선수 모델·경기장 배치를 가져오지 않는다. 조작 구조와 키 배치 같은 관습은 맞출 수 있다(사용자가 요청한 범위).
- 계산은 순수(화면·시계·난수·삼각함수 없음), 상태는 JSON. 방장이 계산하고 손님은 예측.
- 메시지 아끼기 규칙(스냅샷 초당 10, 입력은 바뀔 때만, 사람 8명)을 모든 게임이 지킨다.
- 사람에게 보이는 번호는 등번호(jersey).
