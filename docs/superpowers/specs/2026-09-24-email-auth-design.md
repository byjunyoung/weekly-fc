# 본인인증 — 이메일 코드 로그인

> 2026-09-24. 팀원 피드백("누구든지 위장이 가능하다", "혼자 무한히 대결해 의도적으로 올리고 내릴 수 있다")을
> 받아 사용자가 결정. 방향 질문 여섯의 답 — **이메일 인증**, 명단 번호는 **먼저 고른 사람이 차지**(관리자가 풀어 줌),
> 꾸미기는 **본인 것만**, 대결은 **하루 30판 + 같은 선수 하루 3번**, 내 대결은 **지금처럼 넣기**,
> 관리자도 **이메일 계정**(PIN 없앰). 앞서 카카오 로그인을 보류한 결정(2026-09-24)을 대신한다.

## 1. 왜

지금 "나"는 폰에 저장된 자칭이다. 대결 기록의 이름·꾸미기·홈 라커룸이 전부 그 자칭을 믿는다. 또 대결은
무제한이고 "모르겠음"으로 원하는 선수가 나올 때까지 넘기거나 `?num=N` 으로 한 선수를 불러 몰아줄 수 있다.
판정 제한은 "누가 눌렀나"를 서버가 알아야 셀 수 있으므로 본인인증이 전제다.

비교(요약): 문자 인증은 명단 전화번호로 자동 연결되는 장점이 있었으나 문자 업체·비용이 들고, 카카오는 무료지만
개발자 앱 등록이 필요 — 사용자가 이메일을 골랐다. 명단에 이메일이 없어 번호 잇기 단계가 따로 있다.

## 2. 흐름

```
상단바 [로그인] → 이메일 → 메일의 6자리 코드 → (처음이면) 아직 안 차지된 이름 고르기 → 끝
로그인 뒤 상단바 [이름] → 누르면 로그아웃 확인
```

- **링크가 아니라 코드**: 카톡 인앱에서 열고 메일 앱의 링크를 누르면 다른 브라우저가 열려 세션이 엉뚱한 곳에 남는다.
- 세션(access·refresh 토큰)은 그 기기 localStorage. access 는 1시간, 만료 60초 전부터 refresh 로 갱신.
- 보는 건 누구나. 대결·꾸미기는 로그인 + 이름 차지가 있어야.
- **"나" = 로그인한 이름.** 옛 자칭(`wfc_me`)은 없앤다. 홈 라커룸의 "내 선수"도 로그인해야 보인다.

## 3. 관리자

- `settings.admin_emails`(쉼표 목록)에 있는 이메일로 로그인하면 관리자. 상단바 관리자 버튼은 그때만 보이고, 누르면
  관리자 모드 켜기/끄기(PIN 없음). 관리자 PIN 해시·`verify_pin`·`set_admin_pin`·`import_all` 은 없앤다.
- 선수 페이지(관리자만): "연결된 계정: ab***@gmail.com [풀기]".

## 4. 서버

마이그레이션 `supabase/migrations/20260924200000_email_auth.sql`.

| 표 | |
|---|---|
| `members(user_id uuid pk → auth.users, num int unique → players on delete cascade, email, claimed_at)` | 이름 차지 |
| `votes(id, ts, voter uuid, field, win, lose)` | 제한 세기 — 숫자가 안 바뀐 판도 남긴다 |

| 함수 | 누가 | |
|---|---|---|
| `me()` | 로그인 | `{email, num, name, admin, today, todayBy:{num:횟수}}` |
| `claim(p_num)` | 로그인·미차지 | 이미 차지된 번호면 `'이미 다른 계정이 고른 이름입니다'` |
| `vote(p_field, p_win, p_lose)` | 차지한 사람 | 하루 30판(`'오늘 대결은 여기까지입니다. 내일 또!'`), 같은 선수 3번(`'오늘 이 선수는 더 판정할 수 없습니다'`). 날짜는 Asia/Seoul. 누른 사람은 서버가 정한다 |
| `write_avatar(p_num, p_avatar)` | 본인·관리자 | 남의 것은 `'내 선수만 꾸밀 수 있습니다'` |
| `get_all_full()`·`write_player`·`delete_player`·`write_rotation`·`write_fine`·`delete_fine` | 관리자 | PIN 인자 없앰(`p_payload` 만) |
| `admin_members()`·`admin_release(p_num)` | 관리자 | 차지 목록·풀기 |

- 확인은 전부 `auth.uid()`·`auth.jwt()->>'email'` 로 서버에서. 브라우저가 보내는 "누구"는 받지 않는다.
- 대결 기록(`stat_log`)의 `by`·`by_name` 은 차지한 번호·이름.

## 5. 앱

- `src/lib/auth.ts` — 세션 저장·갱신, `sendCode(email)`, `verifyCode(email, code)`, `logout()`, `accessToken()`.
  라이브러리 없이 Supabase Auth REST(`/auth/v1/otp`·`/verify`·`/token?grant_type=refresh_token`·`/logout`).
- `rpc()` 가 로그인 중이면 `Authorization: Bearer <access>` 를 싣는다.
- `src/react/useSession.ts` — `me()` 결과를 React 로(로그인·차지·관리자·오늘 판수). `wfc:auth` 이벤트.
- 상단바: 로그인 모달(이메일 → 코드 → 이름 고르기), 관리자 버튼은 관리자일 때만.
- 대결: 로그인·차지 확인, 오늘 3번 찬 선수는 짝에서 뺀다, 30판이면 끝 화면.
- 선수 페이지: 꾸미기 버튼은 본인·관리자만. 관리자에겐 연결 계정·풀기.

## 6. 설정

- 메일: Supabase 기본 메일은 조직 멤버에게만·시간당 2통 → **사용자 Gmail SMTP**(앱 비밀번호, 대시보드에서 사용자가 입력).
- 로그인 설정·메일 문구(코드 6자리)는 `supabase/config.toml` 에 선언한 것만 `supabase config push` 로 올린다
  (선언 안 한 설정은 그대로 — CLI 설명). 먼저 `config diff` 로 본다.

## 7. 확인

- 서버(실제 프로젝트): 로그인 없이 대결·꾸미기 거절, 남의 아바타 거절, 31번째 판·같은 선수 4번째 판 거절,
  차지된 번호 거절, 관리자 아닌 계정의 관리자 함수 거절. 시험 계정은 확인 뒤 지운다.
- 폰 폭에서 눌러서: 로그인 → 이름 고르기 → 대결 → 로그아웃, 관리자 풀기.

## 8. 범위 밖

이메일 바꾸기, 기기 여러 대 동시 로그인 제한(허용), 대결 되돌리기.
