# WEEKLY FC — 도트 게임 비주얼 리프레시

## 1. 무엇을 바꾸나

Ant Design 마이그레이션(0~4단계)과 실사 선수 카드(D단계)로 컴포넌트 체계는 다 갖췄지만, 톤 자체("짙은 바탕 + FC 아이템 카드" 9/11 스펙 원안)를 다시 잡는다. 이번엔 **도트(픽셀) 게임 감성으로 전면 커밋** — 폰트·테두리·색 팔레트까지 전부 바꾸고, 겸사겸사 지금 기능 전체를 다시 훑어 안 쓰는 것은 걷어낸다. 홈·스쿼드·매치·운영·선수상세 다섯 화면 전부가 대상이다.

**바뀌지 않는 것**: 서버 계약(Apps Script), 시트 스키마, Astro 완전 정적 빌드 구조, antd 컴포넌트 자체(Modal·Table·Drawer 등 — 이번은 그 위에 입히는 톤 작업이지 컴포넌트를 또 바꾸는 게 아니다).

## 3. 시각 기반

### 색 팔레트
완전 흑백(게임보이식)은 등급(금/은/동)·포지션(GK/DF/MF/FW)·능력치 구간처럼 지금 색으로 의미를 구분하는 자리가 많아 깨진다. **제한된 레트로 팔레트(패미컴/SNES급 규모)로 간다** — 지금의 짙은 배경(`--bg`, `--tint` 등 기존 다크 톤)은 베이스로 유지하고, 그 위에 얹는 강조·상태색만 딱 떨어지는 개수로 줄인다. 정확한 hex 값은 계획 단계에서 확정한다.

**등급(금/은/동) 카드 배경**: 지금은 금속 그라디언트(`--metal-gold` 등)다. 매끈한 그라디언트는 도트 톤과 안 맞는다 — **평평한 단색 블록**으로 바꾼다(그라디언트 자체를 없앤다, 디더링 패턴 같은 흉내는 안 넣는다 — 범위 밖).

### 폰트 — 갈무리(Galmuri), 그러나 전체 적용은 아니다
한글 도트 폰트 갈무리(Galmuri, SIL OFL, jsDelivr 제공)를 확인했다. **다만 실제 서빙 용량을 재보니 한 굵기(woff2)가 300~565KB다** — 이 프로젝트가 지금까지 페이지당 JS/CSS 몇십 KB 단위로 무게를 따져온 것과 비교하면 폰트 하나로 그 몇 배를 더 얹는 셈이다. 그래서 **전체 본문(운영 규칙 긴 텍스트 등)에는 안 쓰고, 제목·숫자(OVR·능력치)·버튼·짧은 라벨류에만 적용**한다 — 도트 룩은 눈에 띄는 자리에 집중되고, 긴 한글 문단은 지금 폰트를 유지해 무게를 지킨다. 굵기는 가장 가벼운 `Galmuri9`(429KB) 하나만 쓴다. 이 트레이드오프는 사용자 확인 없이 내가 판단했다(8절 참고) — 너무 가볍다/무겁다 싶으면 계획 단계에서 뒤집을 수 있다.

### 픽셀 아바타 — PNG + CSS mask 합성
지금 아바타(`src/components/avatar.ts`)는 SVG 문자열을 코드로 조합해 그리는 순수 함수다. 이 계약(동기·문자열 반환)이 4단계 내내 여러 번 검증된 이유가 있다 — `dangerouslySetInnerHTML`을 쓰는 자리들은 이 문자열이 **동기적으로, 항상 같은 입력엔 같은 출력**을 내야 안전하다(이번 세션에서만 `nextUid()` 비결정성·`key={tool}` 재마운트·`id` 유실 버그를 셋 다 겪었다).

그래서 진짜 픽셀 PNG를 쓰되, **캔버스 팔레트 스왑(비동기, 이미지 디코드 필요)은 쓰지 않는다.** 대신:

- 부품 모양마다(얼굴 5·헤어 8·눈 3·유니폼 실루엣 1 = **총 17종**) **알파 전용 흑백 실루엣 PNG** 하나씩만 준비한다(색 정보 없이 "어디가 칠해지는가"만 담음).
- 화면에는 그 실루엣을 겹겹이 쌓되, 각 레이어를 `mask-image: url(부품.png)` + `background-color: <그 부품에 고른 색>` + `image-rendering: pixelated`로 그린다 — 부품 선택은 지금처럼 조합하고, 색은 CSS 배경색 교체로 입힌다. 실제 계산은 브라우저가 매 프레임 하는 게 아니라 CSS 자체가 처리해 동기·저비용이다.
- 실루엣 PNG는 손으로 그리는 대신 **픽셀 격자 데이터(코드)로 한 번 작성해 스크립트로 래스터화**한다 — 지금 SVG 도형(원/사각/육각/다이아몬드/필 등)을 격자에 옮겨 그린 것이라 부품 가짓수·조합 방식은 그대로 유지된다. 새 npm 의존성(이미지 라이브러리)은 추가하지 않는다 — Node 내장 `zlib`만으로 PNG를 직접 인코딩하는 한 번짜리 생성 스크립트를 쓴다.
- 원본 그리드 해상도는 32×32px로 통일하고, 화면에는 지금 `avatarSvg()`가 받는 것과 같은 `size` 값으로 확대 표시한다(`image-rendering: pixelated`라 확대해도 흐려지지 않는다).
- 눈 부품 중 `wide`(놀란 눈, 두 가지 색이 섞인 형태)는 마스크 하나로 색 하나만 입힐 수 있어 재검토가 필요하다 — 마스크를 두 장(흰자/동공)으로 쪼개거나, 이 부품만 재색칠 없이 고정색으로 굽는다. 계획 단계에서 정한다.

### 선수 카드 공유 이미지(`share-image.ts`)
1080×1350 PNG를 만드는 캔버스 코드가 있다 — 이 자리는 CSS mask를 못 쓰는 순수 캔버스 그리기다. 여기서는:
- 갈무리로 그리는 텍스트가 있다면, 그리기 전에 `await document.fonts.ready`로 폰트 로드를 기다린다(안 하면 폰트가 조용히 기본 폰트로 떨어져 캡처된다).
- 아바타는 실루엣 PNG를 `ctx.drawImage()`로 직접 그리되 `ctx.imageSmoothingEnabled = false`로 확대 시 흐려짐을 막고, 색 입히기는 CSS mask 대신 캔버스 컴포지트(`globalCompositeOperation`)로 같은 효과를 낸다.

## 4. 화면별 범위

### 홈
매치 카운트·최근 영상 타일 삭제. 대신 유튜브 채널 링크 하나(외부 이동)를 추가한다. 나머지(스쿼드·라인업·봉사·벌금 타일)는 톤만 바뀐다.

### 매치 — 전체 삭제
`/match/` 라우트, `src/react/match/MatchApp.tsx`, `src/lib/match-videos.ts`, `scripts/fetch-videos.mjs`, `src/data/videos.ts`, 관련 단위 테스트, `Shell.astro`의 상단 탭 항목, `dist.test.mjs`의 관련 항목까지 전부 지운다. `fetch-videos.mjs`가 빠지면 `prebuild`도 그만큼 가벼워진다(이 세션 내내 `npm test` 뒤 `src/data/videos.ts`를 매번 `git checkout`으로 되돌려야 했던 것도 없어진다).

### 운영
기능 변경 없음. 벌금 기준표·현황·내역, 봉사표 전부 그대로, 톤만 도트식.

### 선수상세
능력치·요약·편집·삭제 그대로. 아바타 에디터는 부품 목록 고르는 구조는 같고 미리보기가 픽셀 스프라이트로 바뀐다. 실사 사진 관련 코드(`photoHtml`, 3곳의 호출, `public/players/README.md`, 관련 CSS·테스트)는 전부 되돌린다.

### 스쿼드
명단 3뷰·피치 드래그·포메이션·이미지 공유는 그대로, 톤만 바뀐다. 그리기 도구(`board-draw.ts`, 도구 Segmented, `Drawing`/`Pt` 타입, 그리기 관련 이벤트 핸들러)는 삭제한다.

## 5. 단계 순서

antd 마이그레이션과 같은 구조 — 스펙 하나, 화면(성격)별로 계획을 나눠 SDD로 하나씩 진행한다.

1. **0단계 — 제거**: 매치 탭 전체, 실사 사진(D단계) 전체, 스�쿼드 그리기 도구. 순수 삭제라 시각적 위험이 없고, 이후 단계가 짊어질 범위를 먼저 줄인다.
2. **1단계 — 기반**: 색 팔레트 토큰, 갈무리 폰트 적용 범위, 픽셀 아바타 스프라이트 생성 스크립트 + `avatar.ts` 렌더러 교체, 등급 카드 그라디언트→단색.
3. **2단계 — 홈**: 톤 적용 + 유튜브 채널 링크.
4. **3단계 — 운영**: 톤 적용.
5. **4단계 — 선수상세**: 톤 적용 + 아바타 에디터가 픽셀 스프라이트 미리보기 쓰도록.
6. **5단계 — 스쿼드**: 톤 적용(가장 크다 — 피치·카드·표·공유 이미지 전부).

## 6. 범위 밖

- 실제 손그림 픽셀 아트(이미지 편집 툴로 직접 그리기) — 스크립트로 격자 데이터를 래스터화하는 방식만 쓴다.
- 폰트 서브셋팅(용량 최적화) — 1단계에서 무게가 실제로 문제 되면 그때 별도로 검토.
- 다크/라이트 테마 전환, 새 페이지 추가 — 요청에 없음.
- 눈 부품(wide) 두 색 마스크 분리 여부 확정 — 1단계 계획에서.

## 7. 검증

- 각 단계 끝에서 `npm test`(unit+build+dist) 통과.
- 픽셀 아바타는 컨트롤러가 헤드리스 브라우저로 실측(부품 조합별로 실루엣이 깨지지 않는지, 색 교체가 실제로 반영되는지, 모바일/데스크톱 크기에서 `image-rendering:pixelated`가 유지되는지).
- 공유 이미지(1080×1350)는 실제로 한 장 생성해 픽셀·폰트가 깨지지 않았는지 육안 확인.
- 매치 삭제 뒤 dist 전체에 `match` 관련 흔적(라우트·데이터·번들)이 없는지 스캔(4단계의 `webawesome` 잔존 스캔 테스트와 같은 패턴).

## 8. 내가 판단해서 정한 것 (사용자 확인 없이 결정, 필요하면 뒤집을 것)

- 갈무리 폰트를 본문 전체가 아니라 제목·숫자·라벨에만 쓰기로 함(무게 때문).
- 갈무리 굵기는 `Galmuri9` 하나만.
- 아바타 합성 방식: 캔버스 팔레트 스왑 대신 CSS `mask-image` — `dangerouslySetInnerHTML` 자리들의 동기·결정성 계약을 지키기 위해.
- 실루엣 PNG 생성: 이미지 편집 대신 픽셀 격자 데이터 + Node 내장 `zlib` 스크립트로 래스터화(새 이미지 라이브러리 의존성 추가 안 함).
- 원본 스프라이트 해상도 32×32px 고정.
- 등급 카드는 그라디언트를 완전히 없애고 단색 블록으로(디더링 패턴 같은 대안은 범위 밖으로 미룸).
- 단계 순서를 "제거 먼저(0단계)"로 재배치 — 삭제 대상 위에 새 톤을 또 입히는 헛수고를 막기 위해.
- 팔레트 정확한 hex 값, 눈(wide) 부품 마스크 분리 여부는 계획 단계로 미룸(스펙 수준 결정이 아니라고 판단).
