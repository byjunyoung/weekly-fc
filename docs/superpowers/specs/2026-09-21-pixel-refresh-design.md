## 3. 시각 기반

### 색 팔레트 — [갱신] 전면 교체 아님, 등급만 단색화
지금 색 토큰(`--pos-gk/df/mf/fw`, `--val-a~d`, `--cond-up/mid/down`, `--gold`/`--silver`/`--bronze`)은 이미 "개수 제한·의미 뚜렷·실측 대비(WCAG) 통과"라는, 이번 리프레시가 요구하는 레트로 팔레트의 조건을 이미 만족한다(파일 자체에 대비 실측 기록이 남아 있다). 색상(hue)을 새로 고르는 작업은 하지 않는다.

**등급(금/은/동) 카드 배경만 바꾼다**: 지금은 금속 그라디언트(`--metal-gold` 등)다. 매끈한 그라디언트는 도트 톤과 안 맞는다 — **평평한 단색 블록**으로 바꾼다. 이미 있는 solid 토큰(`--gold: #ffce21`, `--silver: #cfd6de`, `--bronze: #d69256`)에 그대로 연결하면 되고, 셋 다 `--ink`(#121314) 대비 7.18~12.69로 여유 있게 통과한다(직접 계산 확인). 디더링 패턴 같은 흉내는 안 넣는다 — 범위 밖.

### 폰트 — 갈무리(Galmuri), 그러나 전체 적용은 아니다
한글 도트 폰트 갈무리(Galmuri, SIL OFL, jsDelivr 제공)를 확인했다. **다만 실제 서빙 용량을 재보니 한 굵기(woff2)가 300~565KB다** — 이 프로젝트가 지금까지 페이지당 JS/CSS 몇십 KB 단위로 무게를 따져온 것과 비교하면 폰트 하나로 그 몇 배를 더 얹는 셈이다. 그래서 **전체 본문(운영 규칙 긴 텍스트 등)에는 안 쓰고, 제목·숫자(OVR·능력치)에만 적용**한다(1a에서는 버튼·라벨은 뒤로 미룬다 — 아래 갱신 참고) — 도트 룩은 눈에 띄는 자리에 집중되고, 긴 한글 문단은 지금 폰트를 유지해 무게를 지킨다. 굵기는 가장 가벼운 `Galmuri9`(429KB) 하나만 쓴다.

**[갱신] 비트맵 폰트는 원 격자 배수가 아닌 크기에서 흐려진다.** Galmuri9의 권장 렌더 크기는 10px다. 지금 글자 크기 사다리(12~54px)는 10의 배수가 아니다 — 그대로 쓰면 갈무리를 왜 넣었는지 모를 만큼 흐려진다. 그래서 갈무리가 적용되는 자리에만 쓰는 **별도 크기 세트**(`--fs-pixel-sm/md/lg/xl` = 20/30/40/60px, 전부 10의 배수)를 새로 만든다 — 기존 `--fs-*`는 본문용으로 손대지 않는다. 버튼·나머지 짧은 라벨은 이 트레이드오프(새 크기 체계 도입 범위)를 좁게 유지하려고 1a에서는 제외하고, 필요하면 이후 화면별 단계에서 그 화면 몫으로 넣는다. 전부 사용자 확인 없이 내가 판단했다(8절 참고).

### 픽셀 아바타 — [갱신] 기존 SVG 조합 구조 유지 + 헤어·눈은 오픈소스(DiceBear, CC0) path 재사용
지금 아바타(`src/components/avatar.ts`)는 SVG 문자열을 코드로 조합해 그리는 순수 함수다. 이 계약(동기·문자열 반환, 항상 같은 입력엔 같은 출력)이 4단계 내내 여러 번 검증된 이유가 있다 — `dangerouslySetInnerHTML`을 쓰는 자리들은 이 문자열이 **동기적으로, 항상 같은 입력엔 같은 출력**을 내야 안전하다(이번 세션에서만 `nextUid()` 비결정성·`key={tool}` 재마운트·`id` 유실 버그를 셋 다 겪었다). 아래 설계는 이 계약을 그대로 지킨다 — PNG+mask안보다 오히려 더 잘 지킨다(비동기 이미지 디코드가 아예 없다).

**오픈소스 재사용 — 무엇을, 어디까지:**
- 소스는 `@dicebear/pixel-art` 스타일 정의 파일(`@dicebear/styles@10.6.0/dist/pixel-art.min.json`) — 실제로 받아 확인함(`meta.license`): **CC0 1.0(퍼블릭 도메인), 출처 표기 의무 없음**. 16×16 고정 픽셀 캔버스 기준으로, 부품마다 `{"elements":[{"d":"...", "fill":{"name":"hair"}}]}` 형태 — path 하나(또는 여러 개) + 색 이름 placeholder만 담고 있어, 지금 `hairShape()`/`eyesShape()`의 "shape → SVG 문자열, fill은 인자로 받음" 패턴과 사실상 동일하다.
- **헤어(45종 중 우리 8종에 맞는 것 선택)·눈(12종 중 우리 6종에 맞는 것 선택)만 가져온다.** `@dicebear/core` 같은 런타임 npm 패키지는 추가하지 않는다 — 선택한 variant의 `d` 문자열만 코드에 정적으로 복사해 우리 100×100 뷰박스 좌표로 이식한다(원본은 16×16 그리드 기준 좌표라 배치·스케일 변환이 필요하다. 정확한 variant 선정과 좌표 이식은 계획 단계에서).
- **얼굴형(5종)·유니폼 실루엣(1종)은 이 세트에 대응 부품이 없어 계속 직접 그린다** — DiceBear pixel-art는 두상 자체를 고정하고(`canvas.elements`의 고정 skin path) 색만 바꾸는 방식이라 "얼굴형이 여러 종류"라는 개념이 없다.
- **직접 렌더링해서 확인한 결과(스크린샷, 얼굴형 5종 × 대표 헤어 6종 + 눈 3종 조합):** 빌려온 헤어는 DiceBear 고유의 둥근 두상 실루엣에 맞춰 그려져 있어 원형·각짐·육각·갸름 얼굴 위에 얹으면 자연스럽게 읽힌다. 다만 **다이아몬드(현재 정점형) 얼굴형은 정수리가 헤어 실루엣 위로 뾰족하게 튀어나와 어색하다** — 헤어가 "덮이는" 부위가 아니라 "뚫고 나오는" 모양이 된다. 대응: 다이아몬드 얼굴형의 정수리 3~4행을 평평하게 깎아 다시 그린다(부품 개수·코드 계약·라벨은 그대로, SVG path만 조정). 얼굴형을 줄이거나 DiceBear 두상으로 통일하는 대신 이 방법을 택한 이유는 저장된 아바타 코드(`f0`~`f4`)와 `PARTS.face` 배열 구조를 하나도 안 건드려도 되기 때문이다.
- 눈에 "wide"(놀란 눈, 두 색 혼합)처럼 다색 부품이 있어도 문제 없다 — DiceBear variant 형식 자체가 부품 하나당 `elements` 배열(요소마다 자기 색)이라, 마스크 하나에 색 하나만 입힐 수 있던 PNG안의 제약이 애초에 없다.

**렌더링 방식 변경:**
- `image-rendering: pixelated`(래스터 이미지 전용) 대신 아바타 SVG 최상위에 `shape-rendering="crispEdges"`를 건다 — DiceBear 정의 파일도 최상위 `attributes`에 이 값을 그대로 쓰고 있다(확인함). 벡터 path를 확대해도 앤티앨리어싱 없이 칼각으로 남는다.
- **렌더 크기를 16px 배수로 스냅한다** — 실제 코드 4곳을 확인함: `RosterList.tsx:39`(표 칩) 28→**32**, `tokens.css:333`(모바일 카드벽) 68→**64**, `RosterList.tsx:74`(카드 초상) 116→**112**(이미 16의 배수인 `PlayerDetail.tsx:237`의 112와 값이 같아져 두 카드 초상 크기가 통일됨), `PlayerDetail.tsx:208`(아바타 편집 모달 미리보기) 120→**128**(유일하게 키움 — 부품을 고르는 화면이라 더 크고 선명하게). 배수가 아니면 1a에서 겪은 것과 같은 종류의 문제(계산된 스타일은 정상으로 보이는데 실제 렌더는 픽셀 경계가 고르지 않게 뭉개짐)가 생긴다.

### 모서리 — [2026-09-21 3단계] 전역 0
알약 버튼(`--r-full: 9999px`)이 남은 요소 중 도트 톤과 가장 안 맞고, 모든 페이지에 있다. 모서리는 화면별로 나눠 고칠 성질이 아니라 토큰이라, **3단계에서 전역으로 0으로 내린다**(사용자 확인: "지금 전역으로 각지게"). 아직 차례가 안 온 스쿼드·선수상세도 같이 각져지지만 방향이 같으므로 문제 삼지 않는다.

- `tokens.css`의 `--r-sm/md/lg/full`을 전부 `0`으로. **토큰 이름은 그대로 둔다** — 값만 바꿔야 되돌리기가 한 줄이고, 이 토큰을 읽는 규칙 수십 개를 건드릴 이유가 없다.
- antd는 별도 체계라 `src/react/theme.ts`의 반경도 같이 0으로 내린다: 전역 `borderRadiusSM/borderRadius/borderRadiusLG`, `Button`(알약 9999 세 개), `Modal.borderRadiusLG`, `Table.headerBorderRadius`, `Segmented`(알약 세 개). 안 맞추면 antd 부품만 둥글게 남는다.
- 능력치 막대(`.attr-bar`)처럼 둥근 끝이 의도였던 것도 각져진다 — 도트 게임의 막대가 원래 각지므로 의도한 결과다.

### 전신 픽셀 캐릭터 — [3차 갱신, 위 DiceBear 설계를 대체함]
위 "DiceBear path 재사용" 절은 **더 이상 유효하지 않다.** 얼굴만 있는 아이콘이 아니라, 유니폼·반바지·축구양말·축구화를 갖춘 **작은 전신 도트 선수**를 직접 그린다. 이미 `src/components/avatar.ts`에 들어간 DiceBear path 데이터(`DB_HAIR`/`DB_EYES`)와 그 출처 주석은 전부 걷어낸다.

**형식 — 픽셀맵(문자 격자)으로 저작한다.**
- 캔버스는 **24×32** 격자 하나로 고정한다(가로 24·세로 32, 3:4). 부품은 이 격자 위의 레이어다.
- 부품 하나 = 문자열 32줄 배열. 한 글자가 한 픽셀이고 `.`은 투명이다. 글자는 색 슬롯을 가리킨다: `H`(머리색) `S`(피부) `W`(흰자) `E`(눈동자) `M`(입, 피부의 어두운 톤) `K`(유니폼=kit) `D`(유니폼 그늘) `P`(반바지) `O`(축구양말) `B`(축구화).
- 색은 렌더 시점에 팔레트로 주입한다 — `H`/`S`/`E`는 `PARTS`의 기존 색, `K`는 저장된 kit hex(자유 hex 유지), `D`는 kit의 70% 밝기, `M`은 피부의 45% 밝기를 코드로 계산한다. `P`(#e8e8e8)·`B`(#1a1a1a)는 고정, `O`는 kit과 같은 색.
- 레이어 순서: **몸통(전원 공통) → 얼굴형 → 헤어 → 눈 → 입**. 뒤 레이어가 앞 레이어를 덮는다.
- SVG로 낼 때는 **가로로 이어진 같은 색을 한 `<rect>`로 합쳐서** 낸다(픽셀마다 rect를 만들면 768개가 되지만, 합치면 한 명당 60~70개다).

**부품 구성 — 지금 `PARTS` 축과 개수를 그대로 쓴다(저장된 코드 무손상).**
- 얼굴형 5종: `round`·`square`·`hex`·`long`·`wide`. **2~5행(헤어가 닿는 윗부분)은 5종 모두 같은 폭(열 7~16)으로 고정하고, 6~11행의 턱·볼만 다르게** 한다 — 그래야 어떤 헤어를 얹어도 뜨거나 뚫고 나오지 않는다(1b에서 다이아몬드 정수리가 헤어를 뚫고 나왔던 문제의 구조적 해법).
- 헤어 8종: `none`·`short`·`buzz`·`long`(옆머리가 10행까지 내려옴)·`mohawk`(가운데 띠)·`afro`(크게 부풀음)·`side`(비대칭 가르마)·`curly`(정수리가 울퉁불퉁). 1~5행이 기본 영역이다.
- 눈 3종: `dot`(흰자+눈동자)·`line`(가는 선)·`wide`(두 줄짜리 큰 눈). 7행(`wide`는 6~7행) 고정 위치.
- `PARTS.face`의 `shape` 키 중 `circle`→`round`, `diamond`→`wide`, `pill`→`long`은 **그림이 바뀌었으니 라벨도 실제 모양에 맞게 고친다**(인덱스·배열 길이는 그대로라 저장된 코드는 영향 없음).

**두 가지 렌더 모드.**
- **전신(카드·상세·편집 모달)**: 24×32 전체. 호출부가 주는 `size`는 **세로 길이**로 쓰고 가로는 `size × 0.75`로 낸다 — 지금 카드 머리 영역이 `min-height: 104px` 기준이라 세로만 유지하면 레이아웃이 안 흔들린다(112·128·64를 그대로 쓴다).
- **얼굴만(스쿼드 표 32px 칩)**: 같은 픽셀맵을 `viewBox="4 0 16 16"`으로 잘라 머리+어깨만 정사각으로 보여준다. 32px에서 전신은 다리·부츠가 뭉개져 색 덩어리로 보이는 것이 실측으로 확인됐다(사용자 결정: "표 칩은 얼굴만, 카드/상세는 전신").

**덤으로 정리되는 것.**
- `clipPath`가 필요 없어져 `nextUid()`(렌더마다 달라지는 id)를 **없앤다** — 같은 입력이면 항상 같은 문자열이 되어, `dangerouslySetInnerHTML` 자리가 재렌더마다 DOM을 통째로 새로 만들던 문제가 같이 사라진다(D단계 리뷰에서 Minor로 남겨뒀던 항목).
- 테두리·배경은 stroke 대신 **사각형 두 장(테두리색 바닥 + 1픽셀 안쪽에 배경색)**으로 그린다 — 격자에 딱 맞아 픽셀 톤이 유지된다.

### 선수 카드 공유 이미지(`share-image.ts`) — [정정]
> 이전 판(§3 최초 작성)은 이 파일이 캔버스에 선수 아바타를 그린다고 잘못 가정했다.
> 실제 코드(`drawLineupImage()`)를 확인한 결과 **아바타·초상은 전혀 그리지 않는다** —
> 라인업 포메이션 위에 선수 **이름 + 포지션 라벨** 박스만 그린다(1080×1350 PNG). 그래서
> 1b(픽셀 아바타 엔진)는 이 파일을 건드리지 않는다 — 아바타 관련 Path2D/mask 전환
> 자체가 필요 없다.

1080×1350 PNG를 만드는 캔버스 코드가 있다 — 이 자리는 CSS를 못 쓰는 순수 캔버스 그리기다. 갈무리 폰트를 이 캔버스의 제목·이름 텍스트에도 쓸지는 5단계(스쿼드, "공유 이미지 전부" 톤 적용) 범위다 — 그때 적용한다면 그리기 전에 `await document.fonts.ready`로 폰트 로드를 기다려야 한다(안 하면 폰트가 조용히 기본 폰트로 떨어져 캡처된다). 1b 시점엔 해당 없음.

## 4. 화면별 범위

### 홈
매치 카운트·최근 영상 타일 삭제. 대신 유튜브 채널 링크 하나(외부 이동)를 추가한다. 나머지(스쿼드·라인업·봉사·벌금 타일)는 톤만 바뀐다.

**[2026-09-21 2단계 — 톤 적용 확정]** 0단계에서 타일을 덜어낸 뒤의 홈에 실제로 무엇을 입힐지 시안 두 갈래(라벨까지 도트 / 라벨은 유지)를 렌더해 사용자가 **A안(라벨까지 도트)**를 골랐다. 세 가지를 바꾼다.

- **타일 틀**: 둥근 모서리(`--r-md`)를 없애고 `2px` 테두리를 두른다. 지금은 테두리 없이 면만 있어 대시보드로 읽힌다 — 각진 테두리가 들어가야 게임 메뉴 패널이 된다. hover는 배경 밝기 대신 **테두리가 `--fg`로 켜지는** 쪽으로 바꾼다.
- **라벨·값 폰트**: `.tile-label`과 `.tile-duo`도 갈무리로 옮긴다(크기는 `--fs-pixel-sm` = 20px, 원 격자 10px의 배수). `.tile-big`은 이미 갈무리다. **단일 굵기 웹폰트라 굵기를 요구하면 브라우저가 가짜 굵게를 합성해 흐려진다(1a에서 실측으로 당한 것) — 갈무리를 새로 거는 모든 선택자에 `font-synthesis: none`과 `letter-spacing: 0`을 같이 건다.** 본문 긴 글(운영 규칙 등)은 그대로 둔다 — 무게 때문에 좁게 유지한다는 폰트 절의 원칙은 유효하다.
- **「내 선수」를 전체 폭 히어로로**: 1c에서 만든 전신 도트 선수를 이 자리에 세운다(높이 120, 테두리 없이 `bare`). 겸사겸사 격자가 맞아떨어진다 — 지금은 타일 7개라 3열 격자에서 마지막 줄에 하나만 남지만, 히어로(전체 폭) + 나머지 6개(3×2)면 빈칸이 없다. 이름을 안 고른 상태는 같은 자리에 `UNSET_AVATAR` 폴백(번호 자리에 `?`)을 세우고 문구로 안내한다.

구현 주의: 홈 타일은 antd `Card`라 테두리를 CSS로 걸면 antd 규칙과 캐스케이드가 겹칠 수 있다. **적용 여부를 `getComputedStyle`로 실측하고**, 안 걸리면 인라인 style이 아니라 선택자 특정도를 올려(`.rail .tile`) 해결한다 — 인라인으로 박으면 hover에서 테두리 색을 못 바꾼다.

### 운영
기능 변경 없음. 벌금 기준표·현황·내역, 봉사표 전부 그대로, 톤만 도트식.

**[2026-09-21 3단계 — 톤 적용 확정]** 이 페이지는 내용 대부분이 긴 한글 본문(규칙·안내)이라 **본문 폰트는 건드리지 않는다**(§3 폰트 절의 무게 원칙). 톤을 실을 자리는 짧은 라벨과 틀뿐이다.

- **소제목(`.prose h2`)**: 갈무리 20px(`--fs-pixel-sm`)로. 지금 걸려 있는 `letter-spacing: .06em`은 **반드시 0으로 바꾼다** — 비트맵 폰트는 자간이 붙으면 글자가 픽셀 격자에서 밀려 흐려진다(1a 실측). `text-transform: uppercase`는 한글엔 무의미하니 같이 뺀다. 제목 아래 파란 강조 막대는 2px에서 **4px로 두껍게** 해 도트 톤에 맞춘다.
- **앵커 내비(`.tabs a`)**: 같은 이유로 갈무리 20px. 항목이 여섯 개라 좁은 화면에서는 가로 스크롤이 생기는데, `.tabs`가 이미 `overflow-x: auto`라 그대로 둔다.
- **표·패널 틀**: 위 "모서리 — 전역 0"에서 같이 해결된다(`.tbl-wrap`·`.card`·antd Table 전부 토큰을 읽는다). 이 화면 몫으로 따로 할 일이 없다.
- 표 안의 금액·건수를 갈무리로 옮기는 것은 **이번 범위 밖** — antd Table 칸마다 클래스를 심어야 해서 톤 작업치고 침습적이다. 필요해지면 따로 판단한다.

### 선수상세
능력치·요약·편집·삭제 그대로. 아바타 에디터는 부품 목록 고르는 구조는 같고 미리보기가 픽셀 스프라이트로 바뀐다. 실사 사진 관련 코드(`photoHtml`, 3곳의 호출, `public/players/README.md`, 관련 CSS·테스트)는 전부 되돌린다.

**[2026-09-21 4단계 — 톤 적용 확정]** 아바타 미리보기는 1c에서 이미 전신 도트로 바뀌었고, 모서리는 3단계에서 전역으로 각져졌다. 남은 것은 **글자**다. 이 화면의 주인공인 FC 아이템 카드를 도트로 마저 끌고 간다.

- **FC 카드**: `.pcard-pos`(포지션)·`.pcard-stat-val`(카드 안 능력치 숫자)을 갈무리 20px로. OVR은 1a에서 이미 도트다. **모바일 카드벽의 크기 오버라이드(`.pcard-wall .pcard-pos`·`.pcard-wall .pcard-stat-val`)는 지운다** — 18px·16px로 되돌리면 갈무리 격자(10px 배수)에서 벗어나 흐려진다. 오버라이드를 지우면 20px를 그대로 물려받는다.
- **`.pcard-name`(선수 이름)은 그대로 둔다**: 라벨이 아니라 내용이고, 모바일 카드벽에서 폭이 좁아 도트로 키우면 넘칠 위험이 있다.
- **능력치 목록의 값 뱃지**: `.attr-list .val`만 갈무리 20px. **`.val` 자체를 건드리면 안 된다** — 스쿼드 표(5단계)가 같은 클래스를 촘촘한 행에서 쓰기 때문에 여기서 전역으로 키우면 표가 깨진다.
- **모달 제목**: `.ant-modal-title`을 갈무리로, `theme.ts`의 `titleFontSize`를 22→20(갈무리 격자에 맞춤). 아바타 편집·선수 편집·이름 고르기 모달에 모두 걸린다.
- **요약 줄 라벨**: antd Descriptions의 라벨(`미납 벌금`·`봉사`)을 갈무리 20px로.
- **아바타 편집 모달의 부품 버튼(동글·각짐·스포츠…)은 그대로 둔다**: 서른 개가 넘고 현재 14px인데, 갈무리는 10px 배수가 아니면 흐려져 20px로 키워야 하고 그러면 격자가 다시 짜여야 한다. 톤 작업 대비 침습적이라 뺀다.

`.pcard-*`는 스쿼드 카드 뷰(5단계 표면)와 공유한다 — 이번 변경으로 거기도 같이 도트가 된다. 방향이 같으므로 문제 삼지 않는다(3단계 모서리와 같은 판단).

## 5. 단계 순서

antd 마이그레이션과 같은 구조 — 스펙 하나, 화면(성격)별로 계획을 나눠 SDD로 하나씩 진행한다.

1. **0단계 — 제거**(완료, main a5d247a): 매치 탭 전체, 실사 사진(D단계) 전체, 스쿼드 그리기 도구. 순수 삭제라 시각적 위험이 없고, 이후 단계가 짊어질 범위를 먼저 줄인다.
2. **1a단계 — 토큰(폰트+등급 단색화)**: 갈무리 폰트 토큰·크기 사다리(`--fs-pixel-*`) 추가해 제목·OVR·능력치 숫자에 적용, 등급 카드 그라디언트→단색. `tokens.css` 위주 단일 성격 변경이라 먼저 배포해 눈에 보이는 변화를 빨리 낸다.
3. **1b단계 — 픽셀 아바타 엔진**: 픽셀 아바타 스프라이트 생성 스크립트 + `avatar.ts` 렌더러를 PNG+CSS mask 방식으로 교체. 1a가 정한 팔레트·폰트 위에서 진행(1a와 성격이 달라 따로 리뷰). **[2026-09-21 4차 정정]** 실제로는 PNG+CSS mask가 아니라 24×32 픽셀맵 문자열을 그대로 조합하는 방식으로 구현됐다 — §3 "전신 픽셀 캐릭터" 참고.
4. **2단계 — 홈**: 톤 적용 + 유튜브 채널 링크.
5. **3단계 — 운영**: 톤 적용.
6. **4단계 — 선수상세**: 톤 적용 + 아바타 에디터가 픽셀 스프라이트 미리보기 쓰도록.
7. **5단계 — 스쿼드**: 톤 적용(가장 크다 — 피치·카드·표·공유 이미지 전부).

## 9. [2026-09-21] 4b단계 — 전역 마감(탑바·컨트롤·뱃지·모달)

사용자 지시: "도트 게임 테마에 맞춰서 네비게이션 바 등 전면 디자인 일관성 맞춰". 화면별 단계를 돌다 보니 **모든 화면에 걸쳐 있는 공통 부품(탑바·버튼·칩·뱃지·표 머리·모달)만 Pretendard로 남아** 화면마다 도트와 보통 글꼴이 섞여 있었다. 이걸 한 단계로 마감한다.

**크기는 20px(`--fs-pixel-sm`)으로 통일한다.** 시안을 세 벌 렌더해 비교한 결과다 — 10px(갈무리 원래 크기)는 선명하지만 워드마크·내비가 힘을 잃어 "작은 글씨"로만 읽히고, 20px는 탑바·버튼이 확실히 게임 UI로 읽히면서 표 안 뱃지가 굵어지는 정도의 대가만 치른다. 워드마크만 30px(`--fs-pixel-md`)로 키운다.

**대상**
- 탑바: 워드마크(`.mark`), 내비 링크(`.topnav a`), 액션 버튼(antd small Button).
- 컨트롤: 전역 `button` 규칙·`.btn`·`.chip`, antd `Button`·`Segmented`.
- 데이터 표시: 포지션 뱃지(`.pos`), 값 뱃지(`.val`), antd Table 머리.
- 모달·폼: `.ant-modal-title`(+ `theme.ts`의 `titleFontSize` 22→20), `.ant-descriptions-item-label`, 폼 그룹 라벨(`.label`).

**계속 Pretendard로 두는 것** — 원칙은 그대로다. 긴 한글 본문(운영 규칙 문단), 선수 이름, 표 본문의 이름·날짜 같은 **내용**, 그리고 아바타 편집 모달의 부품 버튼 30여 개(격자 재배치 비용).

**구현 주의**
- antd는 글꼴을 컴포넌트 토큰으로 안 정해 준다 — 크기는 `theme.ts`에서, **글꼴은 `tokens.css`의 선택자**에서 건다. 두 군데서 크기를 정하지 않는다.
- antd small Button은 높이가 34px다. 20px 글자가 안 잘리는지 실측하고, 잘리면 `controlHeightSM`을 올린다.
- `.val`을 전역으로 도트화하면 4단계에서 좁혀 뒀던 `.attr-list .val` 규칙이 중복이 된다 — 같이 지운다.
- 스쿼드 표는 열이 많다(선발·아바타·#·이름·포지션·능력치 6·OVR). 뱃지가 20px가 되면 행 높이가 커지므로 **표가 가로로 넘치는지 반드시 실측**하고, 넘치면 표 본문 뱃지만 물러선다.

### [2026-09-21] 4b 최종 리뷰 반영 — 상속 흐림과 10px 토큰

전역 `button` 규칙을 갈무리로 바꾸자 **버튼 안의 모든 후손이 글꼴을 물려받았고**, 그 후손이 자기 크기를 10의 배수가 아닌 값으로 다시 선언한 자리가 전부 흐려졌다(피치 빈 자리 라벨 11개·벤치 줄 칩 90개·「선발」·「전체」·피치 카드 이름). 계산된 스타일로는 전부 정상이라 확대 스크린샷 전수 스윕에서만 드러났다.

**교훈**: `font-family`는 상속된다. 어떤 규칙에 도트를 걸 때는 **그 선택자만 볼 게 아니라 그 안에서 크기를 다시 선언하는 후손을 같이 훑어야** 한다.

**`--fs-pixel-xs: 10px`를 새로 둔다.** 갈무리의 원래 격자 크기라 가장 또렷하다. 벤치 줄 칩·피치 카드 이름처럼 **공간이 빠듯한 자리**는 20px로 키우면 레이아웃이 깨지므로 여기를 쓴다. 넉넉한 라벨은 계속 20px.

**선수 이름은 도트를 유지한다**(사용자 결정). 다만 목록 행(`.bd-pick`)은 **자기 `font-family`를 직접 선언해야 한다** — 모바일 Drawer 안에서는 antd 제외 규칙(`:not(.wfc *)`)이 상속까지 벗겨 Arial로 떨어지기 때문이다. 표 본문의 이름은 계속 Pretendard이므로, 같은 이름이 목록과 표에서 다른 글꼴로 보이는 것은 **의도된 상태**로 남는다.

**단일 출처 위반도 같이 정리한다**: `theme.ts`가 정한 굵기 두 개(`Table.fontWeightStrong: 600`, `Button.fontWeight: 500`)는 `tokens.css`에 덮여 죽은 값이었다 — 400으로 내려 한 곳에서만 정한다.

**회귀 방지 테스트를 넣는다**: `tokens.css`에서 `--font-pixel`을 거는 규칙마다 `font-synthesis: none`·`letter-spacing: 0`·10의 배수 크기를 갖는지 검사한다. 이 프로젝트는 같은 함정에 네 번 빠졌다.

### [2026-09-21] 4c단계 — 표 본문도 갈무리 20px (방침 뒤집힘)

**바로 위(4b) "계속 Pretendard로 두는 것"이 "표 본문의 이름·날짜 같은 내용은 Pretendard"라고 적어 둔 것을 이번에 뒤집는다.** 이유: 스쿼드 명단을 목록 뷰로 보면 선수 이름이 도트, 표 뷰로 전환하면 같은 이름이 Pretendard로 — 뷰만 바꿨을 뿐인데 같은 사람 이름의 글꼴이 갈렸다. 사용자 지시로 이 어긋남을 없앤다: `.ant-table-tbody td`를 4b가 만든 antd 블록에 더해 표 본문 전체(이름·날짜·금액 등)를 20px 갈무리로 올리고, 같은 이유로 UA 기본 글꼴로 떨어져 있던 표 안 「넣기/선발」 버튼도 같이 맞춘다.

**긴 한글 본문(운영 규칙 문단)은 이 뒤집힘의 대상이 아니다** — 그 원칙은 그대로다. 이번에 바뀐 건 표 안의 짧은 값뿐이다.

**실측**: 스쿼드 표(열이 가장 많아 유일한 위험)에서 `pageScrollW === innerW`로 페이지 가로 스크롤은 없다 — 표 자기 안의 가로 스크롤(`tblScrollW 1008 > tblClientW 380~358`)만 그대로이고 이건 원래 허용 범위다. 포지션 칸처럼 좁은 칸에서 뱃지+텍스트가 두 줄로 접혀 줄 높이가 48px(14px 시절)에서 91px로 늘었다 — `theme.ts`의 `Table` 주석을 이 실측치로 고쳤다. 「넣기/선발」 버튼은 `h32 sh28`로 잘리지 않는다. 운영 페이지의 벌금 기준표·미납 현황·벌금 내역, 선수 상세의 벌금 내역도 같은 기준으로 확인했다 — 실데이터가 있는 기준표는 "30,000원"이 그대로 또렷하고, 미납·내역·선수 상세 쪽은 현재 운영상 미납·벌금 기록이 0건이라 실데이터로는 못 보고 같은 칸 구조에 예시 값을 넣어 측정했다(넘치지 않음).

## 13. [2026-09-22] 아바타 커스텀 확장 — 축구 테마 네 부품

사용자: "라커룸엔 유니폼 다양하게 하고 축구 양말. 헤어 스타일 등 커스텀 요소는 축구 테마에 맞게 하면 될듯", "손에 붕대 이런거 가능하게", "장갑도 가능하고". `CODE_SHAPE`가 세그먼트 8개까지 허용하는데 지금 4개(f/h/s/e)만 쓴다는 사실을 §5 계획 때 이미 확인해 뒀다 — 정확히 상한까지 4개(j/o/g/t)를 더한다. **서버 코드는 안 바꾼다** — 정규식이 이미 8개를 허용하고, `parseAvatar`가 모르는 글자를 무시·빠진 세그먼트를 인덱스 0으로 떨어뜨리는 관용적 파싱이라 옛 4세그먼트 코드도 그대로 유효하다.

```
코드   f{n}:h{n}:s{n}:e{n}:j{n}:o{n}:g{n}:t{n}:k#{hex}
        얼굴  헤어  피부  눈  무늬 양말 장갑 테이프 유니폼색
```

- **유니폼 무늬(j) 4종** — 솔리드·스트라이프·후프·긴팔. 새 팔레트 슬롯을 안 만들고 기존 `D`(유니폼 그늘, 원래 옷깃 트림에만 쓰던 색)를 재사용해 몸통(13~15행)에 무늬를 얹는다. 긴팔은 위팔(16~17행)의 맨살을 D로 덮어 소매를 늘린 모양.
- **양말(o) 6종** — 유니폼과 같음(기존 동작, `color:''`→kit) + 화이트·블랙·레드·블루·옐로. 모양은 안 바꾸고 팔레트 O 슬롯의 색 원본만 kit→socks.color로 바꿨다.
- **장갑(g)·손목테이프(t)** — 각 4종/3종, 0번이 "없음"(그 부위를 아예 안 그림). 손목(18행)·손(19행)에 새 팔레트 슬롯(T·G)을 더했다.
- **팔 3행을 부위별로 나눴다** — 16~17행(소매, 긴팔 무늬 전용) · 18행(손목, 테이프 전용) · 19행(손, 장갑 전용). 서로 다른 행이라 세 커스텀이 동시에 켜져도 겹치지 않는다(픽셀 자리 정확히 확인 후 확정 — `sleeves`/`tape on`/`glove on` 오버레이의 색 위치가 BODY의 해당 행 살색 위치와 정확히 일치하는지 좌표를 뽑아 대조했다).
- **`randomAvatar`가 장갑·손목테이프는 85% 확률로 "없음"에 치우쳐 뽑는다** — 균등 추첨하면 아무도 안 만진 30명 전원이 장갑을 낀 채 등장해 어색하다. 유니폼 무늬·양말은 그런 편향 없이 고르게 뽑아 "다들 다르게 보인다"는 기존 취지를 지킨다.
- `AvatarSpec`의 새 네 필드는 **optional**(`jersey?: number` 등)이다 — 이 필드가 없는 옛 스펙 리터럴(`HomeApp.tsx`의 `PLACEHOLDER_SPEC`, 기존 테스트)도 타입이 그대로 맞고, 소비하는 쪽(`paletteOf`·`mapOf`·`serializeAvatar`)이 전부 `?? 0`으로 기본값을 채운다.
- 에디터(`PlayerDetail.tsx`)엔 얼굴형·헤어와 같은 라벨 버튼 그룹으로 4개를 더했다(`유니폼 무늬`·`양말`·`장갑`·`손목테이프`) — 0번이 "없음"/"유니폼과 같음"이라는 텍스트를 가져야 해서, 라벨 없는 색 칸(kit 스와치)이 아니라 기존 `pickGroup` 패턴을 그대로 확장했다.

## 14. [2026-09-22] 피치 품질 — 도트 잔디 + 아바타 카드

사용자: "스쿼드 운동장이랑 위에 선수들 좀 더 퀄리티 높이자 운동장도 도트 기반으로 그래픽 바꾸고 그 위에 선수 카드도 아바타랑 이름, 포지션, 라벨 붙이자".

**피치를 stroke 에서 채운 사각형으로.** 뷰박스 단위가 미터(축구 68×105·풋살 20×40)이고 CSS `aspect-ratio` 가 같은 비율이라 **가로·세로 배율이 언제나 같다**(440/68 = 679/105 = 6.47) — 그래서 `preserveAspectRatio="none"` 이어도 사각형이 정사각 픽셀로 떨어진다. 이 사실이 도트 전환을 가능하게 한 전제다.

- **깎아 놓은 잔디 줄무늬**(축구 10줄·풋살 8줄, 짝수라 위아래 대칭) + **잔디 알갱이 패턴**(4m 타일에 점 두 개). 패턴 id 는 고정값 `wfc-turf` — 한 화면에 피치가 하나뿐이고, 출력이 결정적이어야 한다(아바타에서 uid 를 없앤 것과 같은 이유).
- **선은 0.9m 두께 사각형**(440px 피치에서 약 5.8px). 테두리는 네 변을 각각 채운 사각형으로 낸다.
- **센터서클은 블록 원** — 격자 칸 중심이 반지름 띠 안에 들면 그 칸을 칠한다. 각도를 훑어 중복을 지우는 첫 시안은 칸이 빠져 들쭉날쭉했다(목업에서 눈으로 확인 후 교체). 칸을 훑는 방식은 좌우·상하 대칭이 보장돼 테스트로 지킬 수 있다.
- **카드 한 장 = 윗줄(OVR·자리 라벨) · 아바타 32px · 아랫줄(이름·선수 포지션).** 자리 라벨과 선수 포지션을 **둘 다** 보여주는 게 이 카드의 정보값이다(둘이 다르면 `is-oop` 로 표시되던 것을 이제 눈으로 바로 읽는다). 아바타는 32px — 격자가 24×32 라 32의 배수여야 도트 하나가 화면 픽셀 하나로 떨어진다.

**공간 예산은 실측으로 정했다**(인원 5~11 × 축구/풋살 코트 × 1280/390px 전수):

| 고친 것 | 증상 | 값 |
|---|---|---|
| `.bd-slot` 의 `gap` 을 다시 선언 | 맨 `button` 규칙의 `gap: 8px` 이 상속돼 카드가 112px 로 부풀고 11인에서 GK·CB 가 겹쳤다 | `gap: 0` |
| 카드 폭을 옛 값으로 유지 | 76px 로 넓히면 11인을 풋살 코트(340px)로 바꾼 조합에서 가운데 두 CM 이 1px 스친다(0.22×340 = 74.8px) | `72px`(모바일 66px) |
| 이름·포지션을 한 줄로 | 두 줄이면 카드가 85px — 390px 화면에서 피치가 553px 로 낮아질 때 GK 카드가 2px 겹치고 4px 잘렸다 | 73px |

### 14.1 리뷰에서 잡은 것 (같은 날 수정)

- **좁은 폭에서 GK 카드가 잘렸다.** 피치 높이는 폭에 정비례하는데(aspect-ratio) 카드 높이는 px 고정이라, 조건은 `카드높이/2 < (1 − GK의 y 0.93) × 피치높이`. 58px 옛 카드는 뷰포트 300px 아래에서만 깨졌지만 73px 새 카드는 **370px 아래에서 깨진다** — 360px(갤럭시 S)에서 1px, 320px 에서 5.4px 잘림 + 겹침. 제 전수 실측(1280·390px)에 없던 폭이었다. 좁은 폭을 두 단계로 줄여 고쳤다: ≤420px 은 OVR 을 10px 로 내려 카드 63px, ≤340px 은 아바타를 접고 글자 카드(48px)로 되돌린다. 320~430px 전부 재측정해 겹침·잘림 0.
- **테두리 모서리가 두 번 칠해졌다.** 네 변을 각각 사각형으로 그리니 모서리 T×T 가 겹쳐, 반투명(α .30)이 α .51 로 밝아진 점이 프레임마다 네 개씩 생겼다(20곳). 세로 변을 T 만큼 안으로 넣어 없앴다. **골라인은 3겹**이었다(바깥 테두리 + 페널티 박스 + 골 에어리어가 같은 자리) — 박스의 골라인 쪽 변을 아예 안 그리도록 `frame(..., 'top'|'bottom')` 을 뒀다. 실측으로 모든 자리가 1겹임을 확인.
- **페널티 스폿이 골라인에서 9m 였다**(규정 11m) — 뷰박스 위(y=0)에서 11 을 센 오프바이원. 12.25·91.25 로 고쳤다.
- **풋살 골대 폭이 6m**(규정 3m)로 두 배였다 — 피치 폭의 30% 를 덮고 있었다. 3m 로.
- **풋살 사분원이 골라인 밖으로 삐져나왔다** — `blockRing` 에 y 범위 clip 을 더해 잘라 냈다. 뷰박스 밖 rect 0개 확인.
- **줄무늬 대칭 주석이 사실과 반대였다** — 짝수 줄은 미러 대칭이 아니다(첫 줄과 마지막 줄 색이 다르다). 짝수로 두는 진짜 이유는 **하프라인이 줄 경계에 정확히 떨어지는 것**(105/10, 40/8)이라 주석을 고쳤다.
- **테스트가 약했다.** 리뷰의 뮤테이션에서 줄 수 홀수화·골대 폭 20m·스폿 대칭 이동·하프라인 삭제·블록 원을 각도 훑기로 되돌리기가 **전부 통과했다.** 줄 수와 하프라인 배수, 마킹 좌표, 모서리 비겹침, 블록 원의 8-연결 한 덩어리·빈 행 0 을 단언으로 넣어 다섯 뮤테이션 모두 실패하는 것까지 확인했다.

**남은 것**: 공유 이미지(`share-image.ts`)는 순수 캔버스라 이 도트 피치를 안 쓴다 — 큐 5번(공유 이미지 도트화)에서 같이 맞춘다. 아바타 코드가 손상된 선수의 폴백 번호가 밝은 금속 카드 위에서 `--muted` 라 대비 1.1:1 로 사실상 안 보이는데, 이건 명단 카드에도 원래 있던 문제라 이번 범위 밖으로 뒀다.

### 14.2 [2026-09-22] 피치를 칸 폭까지 (정렬)

사용자 지적: "라인업 뷰에서 스쿼드랑 명단이랑 정렬이 안맞잔하". 실측하니 제목·조작줄·명단은 전부 본문 격자(32~1248)에 맞는데 **피치만 자기 칸 가운데에 떠 있었다**(228~668). 440px 고정 폭이 832px 칸 안에서 가운데 정렬된 탓이다.

세 안을 실제 화면에 CSS 로 입혀 찍어 비교했다 — ①피치만 왼쪽 끝으로(가운데 416px 여백) ②피치 칸을 440px 로 줄이고 남는 폭을 명단이(여백 0, 명단 752px) ③피치를 칸 폭까지 키움. **사용자가 ③을 골랐다.**

- `@media (min-width: 900px)` 에서 `.bd-pitch, .bd-futsal { width: 100% }`. 세로로 쌓이는 좁은 폭은 그대로 둔다 — 거기선 이미 폭을 다 쓰고, 태블릿에서 피치만 과하게 길어진다.
- **피치가 커진 만큼 카드도 키웠다**(1120px 이상): 104×108, 아바타 64px. 64는 32의 정확히 2배라 도트가 안 뭉갠다. **이름·포지션은 10px 그대로 둔다** — 20px 로 키우면 카드가 커진 것보다 글자가 더 빨리 늘어 4자 이름이 오히려 말줄임된다(카드 안쪽 96px 중 포지션·여백을 빼면 69px).
- **[정정] 처음엔 분기를 1000px 로 잡았고 "전수에서 겹침 0"이라고 적었는데 둘 다 틀렸다.** 내 전수 측정은 인원별 **기본 포메이션만**(11인이면 `4-3-3`) 돌렸고, 가장 빡빡한 `3-5-2` 는 한 번도 안 재 봤다. 1000px·3-5-2 에서 GK↔가운데 CB 가 14.7px, 가운데 CM 세 장이 10.2px 씩 겹치고 선택 아웃라인 아랫변이 잘렸다(리뷰가 실측으로 잡음, 나중에 같은 조건을 강제로 재현해 확인). **카드를 구속하는 조건은 §14.1 에 적은 `카드높이/2 < 0.07×피치높이` 가 아니라 이 둘이다**:
  - GK(y .93) ↔ 가운데 CB(y .81) → `0.12 × 피치높이 ≥ 카드높이 + 아웃라인 5px`
  - CM(x .33) ↔ CM(.50) ↔ CM(.67) → `0.17 × 피치폭 ≥ 카드폭`
- 고친 뒤 1280·1120·1119px 에서 **11인 포메이션 4종 전부**(4-3-3·4-4-2·4-2-3-1·3-5-2, 슬롯 라벨로 실제 전환 확인) 겹침 0·아웃라인 여유 13.6px, 인원 5~11 × 축구/풋살 14조합과 899·420·390·360·320px 도 전부 0.
- **알아 둘 것**: 풋살 코트는 20×40 이라 832px 칸을 채우면 **1664px** 가 된다(축구는 1285px). 5~7인용인데 두 화면 높이라 과할 수 있다 — 줄이려면 `.bd-futsal` 만 폭을 묶어야 하는데, 그러면 다시 칸 가운데에 뜨는 문제로 돌아간다.

## 15. [2026-09-22] 포메이션 프리셋 확장 + 자리 기하 계약

사용자가 "포메이션 자유도 높이고" → 선택지에서 **"프리셋 모양을 더 많이"** 를 골랐다. 21종 → **42종**(인원마다 5~7종).

```
 5인  1-2-1 · 2-2 · 3-1 · 1-3 · 2-1-1
 6인  2-2-1 · 2-1-2 · 3-1-1 · 1-3-1 · 3-2 · 2-3
 7인  2-3-1 · 3-2-1 · 2-2-2 · 3-1-2 · 1-3-2 · 3-3
 8인  3-3-1 · 3-2-2 · 2-3-2 · 4-2-1 · 3-1-3 · 2-4-1
 9인  3-3-2 · 3-4-1 · 4-3-1 · 3-2-3 · 2-4-2 · 2-3-3
10인  4-3-2 · 3-4-2 · 4-4-1 · 3-3-3 · 4-2-3 · 5-3-1
11인  4-3-3 · 4-4-2 · 4-2-3-1 · 3-5-2 · 3-4-3 · 5-3-2 · 4-5-1
```

**먼저 고친 것 — 자리 기하를 계약으로 못 박았다.** 같은 결함을 두 번 놓쳤기 때문이다: 헤드리스 "전수 측정"이 **포메이션 축은 인원별 기본값만**(11인이면 `4-3-3`) 돌고 있었고, 가장 빡빡한 `3-5-2` 가 데스크톱(1000~1095px)에 이어 **폰(320~390px)에서도 겹친 채로 배포돼 있었다.** 브라우저로 42종×화면폭을 다 도는 건 느리지만, 자리 좌표는 순수 데이터라 계산으로 전수가 된다 — `tests/unit/formation-fit.test.mjs` 가 화면 구간별 카드 크기와 피치 폭을 표로 들고, **모든 인원 × 모든 모양 × 모든 구간**에서 두 가지를 검사한다:

- 카드끼리 겹치지 않는다 — 두 자리의 `dx`·`dy` 가 **둘 다** 정규화 카드 크기 안으로 들어오면 겹침이다.
- 카드가 피치 밖으로 안 나간다 — 자리는 `translate(-50%,-50%)` 라 가장자리에서 반쪽이 잘린다(맨 아래 GK 가 늘 첫 희생자였다).

표의 카드 폭은 `tokens.css` 선언과 대조하므로, CSS 를 바꾸면 이 테스트가 먼저 깨진다.

**계약을 만족시키려고 같이 바꾼 것**
- **선택 표시를 바깥 `outline` → 안쪽 `box-shadow`.** 바깥 테두리는 피치의 `overflow:hidden` 에 잘려 좁은 화면에서 GK 자리 아랫변이 사라졌고, 카드 바깥 5px 를 차지해 간격 조건까지 빡빡하게 만들었다.
- **341~420px 카드 폭 62 → 56px.** 이 구간의 가장 좁은 피치(309px)에서 11인 5미들이 들어가려면 필요하다.
- **`3-5-2` 좌표를 벌렸다** — 뒤 셋을 평평하게(y .79), 미들 셋을 0.20 간격(x .30/.50/.70), 윙백을 한 줄 내려(y .60).
- **`slotsFor` 폴백 추가** — 11인은 손으로 맞춘 `FORMATIONS` 만 쓰고 있어서 새 모양이 `undefined` 로 떨어졌다. 없으면 모양 문자열에서 만들도록 했다(테스트가 잡았다).

**새 모양을 더할 때의 제약**: 줄 수 2~4, 수비 줄 ≤5, 미드필더 줄 ≤5, 공격 줄 ≤3(`ROW_LABELS` 가 거기까지만 이름을 갖는다). 9인 `4-4` 를 넣었다가 공격 줄 4명이라 그리다 죽는 걸 테스트가 잡아 `2-3-3` 으로 바꿨다.

### 15.1 리뷰에서 더 고친 것

- **자리 밖 선수를 고르면 선택 표시가 통째로 사라졌다.** `.is-selected`(안쪽 그림자)와 `.is-oop`(바깥 그림자)는 명시도가 같고 같은 속성이라 뒤엣것이 이기는데, `pitchHtml` 이 둘을 같이 붙인다. 셋을 다시 정리했다 — 둘 다 **안쪽 링**으로 통일하고 겹칠 때의 규칙(`.is-selected.is-oop`)을 따로 뒀다. 포커스 링도 `outline-offset: -2px` 로 안쪽에 넣어 좁은 화면 가장자리에서 안 잘리게 했고, `box-shadow` 가 버려지는 고대비 모드용 `outline` 폴백도 더했다.
- **56px 카드가 네 글자 이름을 잘랐다.** 56px 이 기하학적으로 필요한 건 **349px 이하**뿐인데 420px 까지 걸어 놔서, 360·390·414px 같은 흔한 폰이 손해를 보고 있었다. 56px 을 `≤349px` 로 좁혔다.
- **테스트의 CSS 대조가 헐거웠다.** "선언된 폭 어딘가에 이 숫자가 있으면 통과"라 한 구간을 되돌려도 같은 숫자가 다른 구간에 남아 통과했다(리뷰 뮤테이션 M2). 구간별 미디어 쿼리를 짚어 보도록 고쳤다.
- **표의 피치 폭도 검증되지 않는 입력이었다**(뮤테이션 M5) — 손으로 적은 숫자를 지우고 `tokens.css` 의 `--max`·`--bd-list-w`·간격·`min(100%, …)` 상한에서 **계산**하도록 바꿨다. 이제 CSS 를 바꾸면 테스트가 따라간다.

**확인**: 계산 전수(42종 × 6구간 × 2코트) + 브라우저로 42종 전부를 1280·390·341px 에서 실제로 골라 보며 겹침 0·잘림 0·자리 수 일치. 뮤테이션 재확인 — 3-5-2 옛 좌표·구간 폭 되돌리기·표의 카드 폭 어긋남·9인 `4-4` 전부 테스트가 잡는다.

## 16. [2026-09-22] 공유 이미지 도트화 — 큐 마지막

화면은 도트로 갔는데 공유 이미지(1080×1350 캔버스)만 옛 선 그림·Pretendard 로 남아 벌어져 있었다. 사용자 요청 둘을 한 번에 처리한다 — "공유 이미지 도트화"와 "공유 이미지 폰트 로드 대기까지 같이 처리해줘".

**그림 데이터를 화면과 공유한다.** 캔버스가 자기 몫의 도트를 따로 그리면 둘이 갈린다 — 그래서 `pitch-view.ts` 의 그리기 원시함수를 **미터 좌표 사각형 목록**으로 바꿔 내보내고(`turfRects`·`markRects`·`turfGrain`), SVG 와 캔버스가 같은 목록을 각자의 방식으로 찍는다. 아바타도 `avatarPixels()` 로 24×32 문자맵+팔레트를 내보내 캔버스가 칸칸이 채운다. **축구 SVG 출력은 한 글자도 안 바뀌었다**(기존 테스트가 좌표를 바이트로 물고 있어 그게 보증이 됐다). 풋살은 잔디 알갱이 타일만 달라졌다 — 아래 잔디 항목 참고.

- **카드**: 화면과 같은 구성에서 OVR 만 뺀다(아바타 · 이름 · 자리 라벨·포지션). 등급 금속색은 그대로 쓰되 숫자는 안 찍는다 — 2026-09-13 결정(단톡방에 능력치가 도는 건 민감)을 유지. 자리 라벨과 포지션이 같으면(GK) 한 번만 쓴다.
- **글꼴**: 갈무리를 쓰되 **실제로 쓸 크기마다 `document.fonts.load()`** 를 건다(20·30·60px). `document.fonts.ready` 만으로는 부족하다 — 그건 *이미 불러오는 중인* 글꼴만 기다리고, 캔버스의 `ctx.font` 지정은 로드를 유발하지 않아 첫 진입에서 대체 글꼴로 굳는다. 캔버스엔 `font-synthesis` 가 없어 굵기는 400 만, 크기는 10의 배수만 쓴다.
- **잔디 알갱이 타일을 경기장 폭에 비례시켰다** — 절대 4m 로 두면 좁은 풋살 코트(20m)에서 다섯 칸밖에 안 들어가 잔디가 아니라 큰 체크무늬가 된다. 폭÷17 이라 축구는 예전과 같은 4m 이고(그래서 화면도 안 바뀐다) 풋살만 잘게 깔린다. **캔버스를 만들다 화면의 결함을 발견한 경우다** — 데이터를 공유했더니 한 번에 고쳐졌다.

### 16.1 리뷰에서 고친 것

- **풋살 카드가 겹치고 잘렸다.** 카드 폭 계수 0.23 이 프리셋의 최소 가로 간격(0.20)보다 커서, 10·11인 다섯 명 줄이 통째로 겹치고 끝 자리가 `clip()` 에 잘렸다 — **기본값 11인 4-3-3 도 포함**. 같은 라인업의 화면은 멀쩡했다(`formation-fit` 이 지킨다). 0.19 로 내렸다.
- **테스트가 소스를 정규식으로 훑고 있었다** — 리뷰 뮤테이션 8종 중 5종이 그냥 통과했다(캔버스가 좌표를 직접 그려도, OVR 을 변수에 담아 찍어도, 카드 폭을 키워도, 아바타 칸을 2.5 로 만들어도). **가짜 2d 컨텍스트로 실제로 그려 보고** 나온 사각형·글자·글꼴을 검사하도록 다시 썼다 — 42종 × 2코트 카드 겹침, 글꼴 굵기·크기, OVR 미출력, 아바타 격자 정수배를 전부 실제 호출로 본다.
- 빈 자리 점선이 화면보다 흐렸다(`--line` → `--hairline-strong` + 어두운 바탕), 네 글자 이름이 공유 이미지에서만 말줄임됐다(안 들어가면 20px 로 한 단계 줄인다), 아바타 코드가 깨진 선수의 칸이 통째로 비었다(화면처럼 번호로 폴백).

캔버스는 실제 렌더 확인도 함께 했다 — 헤드리스에서 모달을 열어 생성된 PNG 를 꺼내 눈으로 봤다(축구 11인·풋살 5인 빈 자리 포함).
