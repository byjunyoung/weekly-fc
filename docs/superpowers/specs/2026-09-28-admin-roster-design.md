# 관리자 모드 정리 — 선수 추가·등번호·배치 대결 (2026-09-28)

사용자: "명단 추가 UI 개선하자. 관리자 모드로 하는 것들 전반적으로 개선. 일관성도 없고 낡은 기능들도 있는듯.
특히 등번호는 뭐가 남았는지 알 수가 없잖아. 능력치 선정도 개별 선정하기보다는 등록할 때 선정을 위한 티어 게임을 따로."

## 1. 지금 문제

| 자리 | 지금 | 문제 |
|---|---|---|
| 명단 [선수 추가] | 빈 번호 페이지(`/squad/N/?new=1`)로 옮겨 편집 모달 자동 오픈 | 추가인데 "선수 편집" 모달. 버튼만 antd 아님 |
| 번호 | 숫자 입력 | 남은 번호를 알 수 없음 |
| 조끼(`vest`, 0~3) | 폼 한 칸 + 선수 페이지 "조끼 N" | 어디에도 쓰이지 않는 시트 시절 칸 |
| 능력치 | 여섯 칸 직접 입력(기본 70) | 티어 게임과 따로 논다 |
| 계정 연결 풀기 | 카드 아래 작은 글씨 | 찾기 어렵다 |
| 매치 삭제 | `Modal.confirm` | 다른 삭제는 전부 `Popconfirm` |

## 2. 결정 (사용자)

- 새 선수 능력치는 **관리자가 등록 직후 배치 대결**로 정한다(팀원 공동 판정안 대신).

## 3. 흐름

```
명단 [선수 추가] → 추가 모달(이름·등번호·포지션·주발)
   [저장하고 능력치 배치] → /squad/place/?num=N  (배치 대결)
   [저장만]               → 선수 페이지 (능력치 '배치 전')
```

### 3.1 등번호 격자
1~99 를 열 칸 격자로. 쓰는 번호는 흐리게, 누르면 "N번은 ○○ 선수" 안내만(고를 수 없음). 추가 모달·편집 모달 둘 다.
기본 선택은 가장 작은 빈 번호. 서버 쪽 겹침 검사는 그대로(`numClash`).

### 3.2 배치 대결 (`src/lib/placement.ts`, 화면 `src/react/squad/PlaceApp.tsx`)
- 항목마다 기존 선수들의 **서로 다른 값**을 줄 세우고 이분 탐색. 한 판 = "누가 더 빠르다? 새 선수 vs 그 값의 선수".
  값이 70·80 근처에 몰려 서로 다른 값이 15개 안팎 → 항목당 4판 안팎, 여섯 항목 약 24판.
- [비슷함] = 그 값으로 확정. [모르겠음] = 같은 값의 다른 선수로 바꿔 묻고, 더 없으면 지금까지 좁힌 구간의 가운데로 확정.
- 끝 위치: 맨 아래 밖이면 최저값 −3, 맨 위 밖이면 최고값 +3, 사이면 두 값의 가운데(1~99 로 자름).
- 상대는 같은 포지션 선수를 먼저.
- **기존 선수 숫자는 움직이지 않고**, 하루 제한도 없다(티어 게임 `vote` 를 쓰지 않는다 — 3번 제한·양쪽 이동 때문).
- 여섯 항목이 끝나면 결과(여섯 값·OVR·예상 티어)를 보여 주고 [저장]에서 한 번에 쓴다. 중간에 나가면 아무것도 안 바뀐다.
- 서버 `public.place_player(p_num, p_stats)` — 관리자만, 1~99 검사, 바뀐 항목만 `stat_log` 에 `via = 'place'` 로 남긴다(선수 페이지 "고친 기록"에 "배치"로 보임).

### 3.3 배치 전 상태
능력치 0 = 배치 전. 티어표·라이벌·대결은 이미 0 을 뺀다. 선수 페이지 능력치 칸에 "아직 배치 전" + 관리자에게 [배치 대결].
능력치가 있는 선수는 관리자에게 [재배치].

## 4. 편집 모달

- 묶음: **기본**(이름·등번호·포지션·세부 포지션·주발) / **운영**(봉사 순번·전화·메모·연결된 계정) / **능력치 직접 고치기**(접어 둠, 보정용).
- 조끼 칸은 폼과 선수 페이지에서 뺀다. 열·값은 남긴다(저장 때 기존 값 그대로 옮김).
- 새 선수의 봉사 순번은 지금 최댓값 + 1(봉사표 자동 계산 맨 뒤).
- `?new=1` 자동 편집 경로는 없앤다 — 추가는 명단 한 곳에서.

## 5. 일관성

- 관리자 버튼은 전부 antd `Button`. 명단 [선수 추가]도.
- 지우기 확인은 `Popconfirm` 하나로(매치 삭제 포함).

## 6. 안 하는 것
- 팀원 공동 배치 판정, 배치 결과 미세 조정 슬라이더.
- `vest` 열 삭제(데이터는 둔다).

## 7. POTM 능력치 보상 (같은 날 추가)

사용자: "POTM 먹으면 능력치 상향되는거 반영됐나?" → 없었다. 권장안으로 결정.
- 경기 다음 날 0시 5분(서울, `pg_cron` 작업 `settle-potm`)에 전날까지 끝난 매치의 1위에게 여섯 항목 +1(99 가 끝, 배치 전 0 은 그대로). 공동이면 모두, 표가 없으면 아무도.
- `potm_awards` 한 줄로 매치당 한 번만. 기록은 `stat_log.via = 'potm'`, 선수 페이지엔 "POTM 보상 · …".
- 이 규칙을 넣은 2026-09-28 이후 매치부터. 9/26 매치(POTM 김효종)는 소급 여부를 따로 정한다.
