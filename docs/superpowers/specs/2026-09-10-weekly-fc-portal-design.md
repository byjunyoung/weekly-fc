# WEEKLY FC 포탈 설계

2026-09-10. 모바일 앱 흉내를 내던 단일 index.html을 웹 친화 반응형 포탈로 다시 짠다. 구조는 Football Manager의 화면 문법을 따르되 배경은 밝게, 절제는 포트폴리오 사이트(byjunyoung.github.io)와 같은 규율로. 전술보드(tactics-board)는 이 포탈 안으로 흡수한다.

결정을 바꾸면 이 문서부터 고친다.

## 1. 결정 요약

| 항목 | 결정 |
|---|---|
| 스택 | Astro 정적 사이트. 데이터는 브라우저에서 Apps Script로 받음 |
| 전술보드 | 포탈 `/tactics/`로 흡수. 옛 레포 아카이브·Pages 종료. 옛 주소는 버림 |
| 공개 범위 | 전부 공개. 팀 데이터 페이지는 noindex, `/tactics/`·`/about/`만 검색 허용 |
| 신원 | 가입·로그인 없음. 명단에서 본인을 골라 기기에 저장(개인화용). 관리자는 PIN |
| 참석 입력 | 카톡 투표 결과 텍스트 붙여넣기 → 명단 대조. 포탈 투표는 안 만듦 |
| 새 기능 | 시즌 기록판 · 정산 현황판 · 영상/리캡 아카이브 · 팀 소개·모집 |
| 정보구조 | 홈 · 스쿼드 · 매치 · 기록 · 전술 · 소개 (여섯 갈래, 좌측 사이드바) |
| 톤 | 구조만 FM(사이드바·탭·밀도 높은 표·색코딩), 배경은 밝게. 다크 테마 없음 |
| 댓글 | 뺀다. 매치 0건이라 쓰인 적 없음. 대화는 카톡 |
| 코드 | 이관 아님, 재작성. 시트·API 계약만 유지 |

## 2. 전제가 된 사실

2026-09-10 라이브 데이터 확인 결과.

- 시트: 선수 30명, 라인업 1개, 매치 0, 벌금 0, 댓글 0.
- 유튜브 채널(`UCfL5rqpEVpMPe-FNG2UvobA`): 영상 15개(2026-04-25 ~ 09-05). 제목이 `YYMMDD | 위클리FC [풋살] N파전 [| 메모] [| 장소]` 꼴. 날짜 접두사 없는 영상도 있음(무시 대상).
- 앱의 `getChannelVideos`는 빈 배열을 돌려줌 — 채널 RSS엔 영상이 있으므로 Apps Script 쪽 버그. 재배포 때 고친다.
- 결론: 매치 기록은 시트가 아니라 유튜브에 있다. 기록·정산 화면은 데이터가 쌓여야 의미가 생기므로, **첫 기록을 쉽게 만드는 흐름**(3.4)이 핵심이다.

`/tactics/`는 사이드바를 접고 전체 폭을 쓴다.

### 3.2 주소

```
/weekly-fc/                    홈
/weekly-fc/squad/              스쿼드 표
/weekly-fc/squad/9/            선수 (1~99 자리를 빌드 때 미리 생성, 내용은 브라우저에서)
/weekly-fc/match/              매치 목록
/weekly-fc/match/?d=2026-09-05 매치 상세 (날짜는 무한이라 쿼리)
/weekly-fc/record/             기록 — 시즌 탭
/weekly-fc/record/fines/       기록 — 정산 탭
/weekly-fc/record/duty/        기록 — 봉사 탭
/weekly-fc/tactics/            전술보드
/weekly-fc/about/              팀 소개·모집·규칙
```

없는 선수 번호·없는 날짜는 그 페이지 안에서 "없음"을 보여준다(404 아님).

### 3.3 홈

```
최근 매치     스코어(있으면) · 유형 · 참석 인원 · 영상 썸네일 → 매치 상세
이번 달 봉사  당번 두 명 · 완료 여부
미납 알림     n건 · 합계 → 정산
내 자리       (이름을 골랐을 때만) 내 미납 n건 · 내 봉사 차례 n월 → 내 선수 페이지
```

### 3.4 매치

**목록** — 줄 보기 / 썸네일 보기 전환.

- 줄: 날짜 · 장소 · 유형 · 결과(있으면) · 참석 인원 · 영상 아이콘. 연도별 접힘.
- 썸네일: 영상 있는 매치만 유튜브 썸네일 격자. 이것이 영상 아카이브다.

**상세** — 탭 셋.

- 개요: 날짜 · 장소 · 유형 · 팀 편성과 결과(있으면) · 참석자 목록 · 영상 임베드.
- 라인업: 저장된 배치를 피치 위에. 없으면 "전술보드에서 만들기" 링크.
- 리캡: 카드 미리보기 + [이미지로 저장]. 4.5 참조.

**관리자 흐름**

```
[영상에서 가져오기]
  채널 영상 제목 파싱 → 날짜·유형·장소
  시트에 없는 날짜만 목록 → 체크 → 한 번에 매치 행 생성
  날짜 접두사 없는 영상은 목록에서 제외

[참석 채우기]  (매치 상세 안)
  텍스트 붙여넣기 → 줄 단위로 명단 이름과 대조
  → 매칭된 이름은 체크, 못 찾은 줄은 따로 표시 → 손으로 고침 → 저장

[결과 적기]
  유형별 팀 이름·선수·승점, 우승 팀. 전부 선택 항목
```

카톡 투표 결과의 정확한 텍스트 형식은 샘플을 받은 뒤 파서를 맞춘다. 그전까지는 "한 줄에 이름 하나"와 "쉼표·공백 구분"을 모두 받는 기본 파서로 간다.

### 3.5 스쿼드

**표** — 번호 · 이름 · 포지션 · 주발 · PAC DRI PAS SHO DEF PHY · OVR · 출석률. 컬럼 머리 클릭 정렬, 포지션 필터(GK/DF/MF/FW), 이름 검색. 카드 보기는 없앤다.

**선수 페이지** — 탭 없이 한 페이지.

```
위    카드 한 장: 번호 · 이름 · 포지션 · 주발 · 조끼 · OVR · 등급 · 능력치 6종 막대
중간  참여 이력: 나간 매치 목록 · 출석률 · 이긴 매치 수(결과 있는 매치 기준)
아래  벌금 누계 · 미납 · 봉사 순번과 다음 차례
관리자  [편집] 기본 정보·능력치 · [삭제]
```

### 3.6 기록

- 시즌: 출석률 순위표(출석 수 / 매치 수) · 총 매치 수 · 유형별 수 · 개인 승률(이긴 팀 소속 횟수 / 결과 있는 매치 참석 수). 시즌 = 연도.
- 정산: 벌금 누계 · 미납자 목록 · 유형별 합계 · 매치별 내역. 관리자는 납부 체크·추가·삭제.
- 봉사: 로테이션 표(연·월·당번 둘·완료). 다음 차례 강조. 관리자는 완료 체크·당번 수정.

### 3.7 전술

tactics-board의 피치·포메이션·드로잉(화살표·존·펜)·줌·가로세로 전환·축구/풋살/7인제를 그대로 가져온다. 여기에:

- 명단 불러오기: 스쿼드에서 골라 배치 → 예전 라인업 빌더를 대체.
- 저장: 매치를 골라 라인업으로 붙임(관리자). 이름 없이 로컬에만 두는 것도 가능.
- 검색 유입용이라 이 페이지만 `index` 허용, 메타·FAQ 스키마는 옛 파일에서 옮기되 주소는 새 것으로.

### 3.8 소개

한 페이지 흐름, 목차 앵커.

```
팀 소개 → 언제 어디서 → 참여 방법(첫 매치 3단계 · 자기소개 양식 · 상시 모집)
→ 회비·벌금 표 → 봉사 → 통장 → 에티켓 → 오픈카톡 링크
```

기존 규칙 6그룹의 사실은 그대로, 겹치는 문장은 정리. 벌금 표는 코드 상수(4.4)와 같은 값을 보여준다.

### 3.9 시각 규칙

- 색·치수·글자 크기는 `src/styles/tokens.css`에서만. 컴포넌트에 hex·px 금지.
- 출발점은 포폴 팔레트(흰 바탕 · #161616 글자 · #6b6b6b 보조 · #d6d6d2 선 · #f7f7f5/#efefec 면). Pretendard Variable 하나. 각진 모서리, 1px 선, 그림자 없음, 모션 없음.
- 포지션 색은 기존 것 유지(GK 주황 · DF 파랑 · MF 초록 · FW 빨강) — 팀원이 익숙하다.
- 색코딩 4단계: 능력치는 84 이상 / 69~83 / 55~68 / 55 미만. 출석률은 80% 이상 / 60~79 / 40~59 / 40 미만. 미납은 강조색 하나.
- 표: 머리 고정, 정렬 가능, 좁은 폭에서 가로 스크롤(본문은 절대 가로 스크롤 안 남).
- 라이트 고정. 시스템 다크 설정을 따르지 않는다.

## 4. 데이터·기술

### 4.1 구성

```
weekly-fc/
  src/styles/tokens.css       색·치수·글자 — 유일한 출처
  src/layouts/Shell.astro     사이드바 · 모바일 헤더 · noindex 메타
  src/pages/                  index · squad/ · squad/[num] · match/ · record/ · tactics · about
  src/lib/api.ts              Apps Script 호출 한 곳 (읽기 캐시, PIN 쓰기)
  src/lib/me.ts               내 이름 (localStorage: 선수 번호)
  src/lib/rotation.ts         봉사 로테이션 계산 (기존 로직 이식, 2026-01 기준 매월 2명 슬라이딩)
  src/lib/parse.ts            유튜브 제목 파서 · 붙여넣기 파서
  src/components/             Table · Pitch · PlayerCard · Recap · Tabs …
  apps-script.gs
  tests/                      파서·로테이션 단위 테스트, dist 검사
  .github/workflows/pages.yml
```

- Astro `base: '/weekly-fc'`. 의존성은 astro와 sitemap뿐. 추가하려면 이유를 적고 사용자 확인.
- 데이터는 페이지 로드 때 `getAll` 한 번 받아 메모리·localStorage에 캐시(기존 `saveCache` 방식). 관리자 쓰기 뒤엔 다시 받는다.
- 관리자: `verifyPin` 뒤 PIN을 sessionStorage에. 쓰기 액션은 전부 PIN 동봉. 전화번호는 `getAllFull(pin)`에서만.

### 4.2 시트 변경

시트가 비어 있어 지금이 바꿀 때다.

```
매치기록   id · date · location · youtube · type · attendees · teams · winner
           type    "2파전" | "3파전"
           attendees  이름을 쉼표로 (시트에서 읽히게 이름 유지)
           teams   JSON [{name, players[], points}] — 없으면 빈칸
           winner  팀 이름 — 없으면 빈칸
           (team_a/team_b/score_a/score_b 는 없앤다)
라인업     id · match_id · name · formation · assignments   (match_id 추가)
선수명단 · 벌금 · 봉사로테이션   그대로
댓글       시트는 두되 읽지 않는다
```

Apps Script: `MATCH_COLS`·`LINEUP_COLS` 갱신, `getChannelVideos` 수정, `addComment`·`getComments`·`deleteComment` 제거. 재배포는 "기존 배포의 새 버전"으로(주소 유지). `SPREADSHEET_ID` 속성 확인.

### 4.3 파서

**유튜브 제목** — `^(\d{6})\s*\|` 로 시작하는 것만. 날짜 = 20YY-MM-DD. 유형 = `(\d)파전`. 장소 = `|`로 나눈 마지막 조각에 "공원"·"풋살장"이 있으면 그것. 나머지 조각은 메모로 버린다.

**붙여넣기** — 줄바꿈·쉼표·공백으로 토큰화 → 각 토큰을 명단 이름과 정확 일치 → 없으면 공백 제거 후 부분 일치 → 그래도 없으면 "못 찾음"으로 표시. 숫자·이모지·"참석"·"불참" 같은 단어는 버린다. 샘플을 받으면 이 규칙을 맞춘다.

### 4.4 규칙 상수

벌금 유형·금액, 회비, 봉사 인원(2명)은 `src/lib/rules.ts` 한 곳. 소개 페이지의 표와 정산의 자동 금액이 같은 값을 쓴다.

### 4.5 리캡 카드

브라우저 canvas로 1080×1080 PNG. 내용: 날짜 · 장소 · 유형 · 결과(있으면) · 참석자 이름 격자 · 라인업 있으면 피치 도형 · 하단 WEEKLY FC 마크. 유튜브 썸네일은 CORS 때문에 넣지 않는다. [이미지로 저장] → 사용자가 카톡에 붙인다.

### 4.6 전술보드 흡수

tactics-board `index.html`의 스크립트·스타일을 `src/pages/tactics.astro` + `src/components/Pitch.ts`로 옮긴다. 색·치수는 토큰으로 치환. 명단 불러오기·저장은 `api.ts`·`me.ts`를 통해 붙인다. 옛 레포: 아카이브(GitHub 설정), Pages 끔. 옛 파일의 canonical·sitemap·robots는 새 주소로 다시 쓴다.

### 4.7 검색 노출

- `Shell.astro`가 기본으로 `<meta name="robots" content="noindex">`. `/tactics/`·`/about/`만 이 메타를 빼고 sitemap에 넣는다.
- `robots.txt`: 전체 허용 + sitemap 주소. (noindex 메타가 페이지별로 막는다.)

### 4.8 배포·검증

- GitHub Actions: main push → `npm ci` → `astro build` → Pages 배포. Pages 소스를 "GitHub Actions"로 바꾼다.
- `npm test` = 단위 테스트(파서·로테이션) + 빌드 + dist 검사(모든 주소 존재, base 경로, noindex 메타 유무).
- 화면 확인: 데스크톱(1280)·모바일(390) 폭 스크린샷을 사용자에게 보여주고 승인 후 push.
- push는 byjunyoung 계정(`gh auth switch --user byjunyoung`, 끝나면 복귀). 커밋 identity는 이 레포에 로컬로 설정해뒀다.

## 5. 범위 밖

로그인·계정 · 예정 경기·일정 · 포탈 안 참석 투표 · 알림 · 다크 테마 · 댓글 · 득점/MOM 기록(시트에 칸이 없다) · 카톡 자동 연동(공식 API 없음).

## 6. 열린 의존

- 카톡 투표 결과 텍스트 샘플 한 건 — 붙여넣기 파서 정밀도.
- 소개 페이지의 팀 소개 문장 — 사용자가 준다. 그전까지는 규칙 페이지의 기존 문장으로 채운다.
