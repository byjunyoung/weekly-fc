# 포털 덜어내기 + 신규 멤버 안내(2026-11-06)

> 사용자: "우리 포탈 기능 좀 정리할까? 많이 안쓰는 기능들. 그리고 신규 멤버 전용 온보딩에 필요한 페이지가 하나 있으면 좋을 것 같음."
> 쓰임 실측(11-06): 대결 투표 누적 663·최근 2주 110, 매치 등록 33. 방명록 4건(마지막 09-28), POTM 투표 3건(09-26), 벌금 기록 0건.
> 사용자 결정: 방명록·POTM·벌금 기록을 뺀다, 메뉴 8 → 6, 벌금은 **기록 기능만** 빼고 규칙의 벌금표는 둔다,
> 안내 페이지는 새 멤버가 **이름 고르기까지** 가 보게 권한다. 다만 사용자가 바로잡음: "포털 가입은 필수는 아니고
> 그냥 재미로 하는거다. 유툽 채널에 영상이 올라간다 이런거 안내해줘야 할듯." → 가입은 권유, 필수처럼 쓰지 않는다.
> 2026-09-25 POTM 스펙과 2026-09-26 POTM 당일 투표, 방명록 관련 결정을 덧씌운다.

## 1. 왜

- 새 멤버가 받는 안내는 오픈채팅 봇 메시지 하나뿐이다. 그 메시지가 가리키는 카톡 공지는 게시 기한이 지나면 지워진다.
  → 봇의 「공지사항 보기」 자리에 넣을 **사라지지 않는 링크**가 필요하다.
- 새 멤버는 팀이 뭘 하는지(경기 영상이 유튜브에 올라간다, 포털이 있다)를 들을 곳이 없다.
- 팀원 37명 중 이름을 고른 계정은 9개. 새 멤버가 들어올 때 권해 보기 좋다. 단 포털은 재미로 쓰는 것이라 필수가 아니다.
- 안 쓰는 기능은 메뉴와 화면을 복잡하게만 만든다.

## 2. 메뉴(8 → 6)

```
지금                 바뀐 뒤
라커룸               라커룸
명단                 명단
라인업 ─┐
매치  ──┴──────→    매치   [지난 경기 | 라인업 짜기]
티어                 티어
전술                 전술
규칙 ──┐
자료 ──┴──────→    안내   [처음 왔다면 | 규칙 | 자료]
```

- 티어는 따로 둔다. 지금 가장 활발한 기능(대결 투표)이라 다른 메뉴 안에 넣으면 찾기 어려워진다.
- 묶인 메뉴는 페이지 위에 하위 탭 줄을 둔다. 기존 주소(`/matches/`, `/lineup/`, `/rules/`, `/kit/`)는 그대로 살린다.
  카톡에 이미 뿌린 링크가 깨지지 않게 하려는 것이다(내 결정).
- 상단 메뉴의 활성 표시는 묶인 하위 주소 어디에 있든 상위 메뉴가 켜진다.
- 「라인업 짜기」 탭 = `/lineup/`. 팀짜기(`/matches/new/`)는 지금처럼 매치 목록의 [새 매치] 로 들어가고, 그 화면에서는
  「지난 경기」 탭이 켜진 채로 탭 줄을 보인다(내 결정).
- `/rules/` 에는 이미 `.tabs` 목차 줄이 있다. 하위 탭 줄과 두 겹이 되므로 눈에 구분되게 하거나 합친다(만드는 쪽이 정함).
- 관리자 [통계]는 지금처럼 따로 두되, 표의 방명록·POTM 열만 뺀다.

- **같은 날 다섯으로**(사용자 "명단이랑 티어도 하나로 합치자"): 티어를 명단 아래로 — 명단 = [선수(`/squad/`) | 티어(`/tier/`)].
  상단은 라커룸·명단·매치·전술·안내. 위 "티어는 따로 둔다" 는 이걸로 덧씌운다. 주소는 그대로.
- **티어는 하위 탭 줄이 아니라 화면 안 보기 전환으로**(사용자 "명단 누르면 티어 메뉴가 생겨버리네? 하단 탭으로 넣어야지"): 위 줄을 덧씌운다.
  상단 메뉴 이름은 안의 보기를 아우르는 **「선수」**("메뉴가 탭을 포괄하는 명칭이어야지"). 선수 화면 제목 아래 첫 줄에 [표 | 아바타 | 티어],
  티어를 고르면 같은 화면에서 티어표·대결이 열리고 주소가 `/tier/` 로 바뀐다. `/tier/`·`/tier/?num=N` 옛 링크는 그 보기로 바로 연다.
  보기 전환을 맨 앞줄에 둔 건 티어가 옮겨 온 걸 놓치지 않게 하려는 것("자주 들어가서 옮겨진 거 모르는 거 유의").
- **탭은 한 가지 모양·한 자리**(사용자 "티어가 기본뷰", "기본값이 가장 왼쪽 탭이어야지", "탭 스타일이 왜 메뉴마다 다 다르냐 통일해"):
  선수·매치·안내 모두 **제목 바로 아래** 같은 탭 줄(`.subnav`, `react/SubTabs.tsx`·`components/SubTabs.astro`)을 쓴다. Shell 은 탭을
  그리지 않고 각 화면이 제목 아래에 그린다(불러오는 화면 `Loading` 도 같은 자리에). 선수 = [티어 | 표 | 아바타], 가장 왼쪽인 티어가
  기본이라 상단 「선수」 메뉴는 `/tier/` 로 간다. 표·아바타는 `/squad/`. 위의 [표 | 아바타 | 티어] 보기 전환(칩)은 이걸로 덧씌운다.
  규칙: **가장 왼쪽 탭 = 그 메뉴의 기본 화면**, 메뉴 이름은 탭들을 아우르는 말.
- **라커룸 단체 사진 띠 삭제**(사용자 "단체사진 좀 촌스럽다 빼던지 더 세련되게"): 빼는 쪽으로(내 결정). 그림 내려받기는 안내 > 자료에 그대로.
- **탭 시인성**(사용자 "탭이 좀 시인성이 안좋다 각 메뉴들"): 상단 메뉴의 안 켜진 글자색 `--muted`(55%) → `--body`(70%),
  하위 탭은 본문 14px 흐린 글자 → 상단과 같은 도트 20px·`--body`, 활성 밑줄 3px.

- **시작하기 + 규칙 = 「가이드」 한 페이지**(사용자 "가이드에 규칙이랑 시작하기 하나로 퉁치자 별로 내용 차이도 없구먼"): 안내 = [가이드 | 자료].
  `/guide/` 에 소제목 다섯 — 언제 어디서 · 벌금 비용(벌금표·통장) · 음료 봉사(봉사표) · 에티켓 · 영상 포털(유튜브·인스타·이름 고르기 버튼).
  새 멤버가 먼저 볼 벌금·봉사를 위쪽에 둔다. `/rules/` 는 `/guide/` 넘김 페이지, 옛 `/record/*` 넘김은 `/guide/#fees`·`#duty` 로.
  아래 §3 과 그 밑의 "한 화면 분량"·"규칙 페이지 한 단" 기록은 이걸로 덧씌운다.

## 3. 안내 > 처음 왔다면 (`/guide/`, 새 페이지)

목표: 팀이 어떻게 굴러가는지 한 번에 알게 하고, 마음이 있으면 **로그인 → 내 이름 고르기**까지 가 보게 한다.
꼭 알아야 하는 것(1~3)과 재미로 하는 것(4~5)을 눈에 띄게 나눈다. 포털 가입을 의무처럼 쓰지 않는다.

```
── 꼭 알아 둘 것 ──
1. 환영 — WEEKLY FC 한 줄 소개
2. 한 주 흐름 — 카톡 투표 → 참석 → 당일 정산
3. 언제·어디서·비용·모임 통장 — 시간·장소·통장은 rules 와 같은 상수(MATCH_TIME·PLACES·BANK), 비용은 상수가 없어 rules.astro 의 문장을 옮긴다

── 재미로 하는 것 ──
4. 경기 영상 — 매치 영상이 유튜브 채널에 올라간다. [유튜브 채널](LINKS.youtube) + 포털 [매치] 탭 링크.
     인스타그램(LINKS.instagram)도 같은 줄에.
5. 포털 — "필수는 아니고 재미로" 라는 말을 그대로 밝힌다. 이름을 고르면 할 수 있는 것(내 선수 카드 꾸미기, 티어 대결)을
   한두 줄로 소개하고 [로그인하고 내 이름 고르기] 버튼
     · 버튼은 상단의 로그인 창(TopbarActions)을 그대로 연다. 새 로그인 화면을 만들지 않는다.
     · 이미 이름을 고른 상태면 "○○ 님으로 연결됨" + 내 선수 페이지 링크
     · 명단에 이름이 없으면 "아직 명단에 없으면 단톡방에 알려 주세요"(관리자가 먼저 추가해야 고를 수 있음)

── 마무리 ──
6. 에티켓·문의는 단톡방
```

- **같은 날 간소화**(사용자 "안내 페이지 좀 뎁스 줄이고 간소화"): 위 묶음 제목 단(꼭 알아 둘 것·재미로 하는 것·마무리)을 없애고
  소제목 셋으로 줄였다 — 「매주 이렇게」(투표·시간 장소·정산 통장·규칙 링크를 목록 하나로), 「경기 영상」, 「포털」. 에티켓 목록은
  규칙 페이지에 있어 뺐고 끝에 "궁금한 건 단톡방" 한 줄만. "필수는 아니고 재미로" 는 포털 칸에 그대로.
- **최종 모양 — 한 화면 분량**(사용자 "안내 페이지 확! 줄여줘"): 소제목을 전부 없애고 네 덩이만. ① 시간·장소 + 투표·정산 한 문단
  ② 벌금·음료 봉사 면(card) + 규칙 링크 ③ 경기 영상 한 줄 + 유튜브·인스타 ④ 포털은 필수 아님 + 버튼. 환영 인사·통장 계좌·
  끝인사는 뺐다(계좌는 규칙 페이지에). 아래 줄들은 그 전 단계의 기록이다.
- **이름은 「시작하기」**(사용자 "처음 왔다면 → 문구 촌스러움", 후보 넷 중 고름): 하위 탭·페이지 제목·라커룸 칸 모두. 이 문서 위쪽의
  「처음 왔다면」은 전부 「시작하기」로 읽는다. 주소 `/guide/` 는 그대로.
- **벌금·음료 봉사 강조**(사용자 "벌금이랑 음료 봉사 처음 왔다면에 강조해야지"): 「매주 이렇게」 바로 아래에 「벌금 · 음료 봉사」 칸을
  기존 `.card` 면으로 띄운다 — 지각·노쇼 금액(굵게), 미리 공지하면 면제, 매월 봉사 인원과 하는 일, 규칙 링크. 값은 rules.ts 상수.
- **규칙 페이지도 같은 날 한 단으로**(사용자 "규칙도 뎁스가 너무 깊어"): 제목 아래 목차 줄(`.tabs`, 여섯 항목)을 없애고 소제목
  여섯 → 넷(언제 어디서·비용 벌금·봉사·에티켓). 「참여 방법」과 접어 둔 자기소개 양식은 뺐다(안내 페이지와 봇 메시지가 맡음).
  「모임 통장」은 비용 칸의 한 줄로(모임 시작일은 뺌). `#fees`·`#duty` 주소는 그대로 — 넘김 페이지와 라커룸 봉사 칸이 쓴다.
- 자기소개 양식은 넣지 않는다. 봇 메시지가 이미 보낸다.
- 링크 미리보기(og) 이미지는 기존 `public/og.png` 를 그대로 쓴다(내 결정). og 렌더러는 레포에 없고(예전 것은 임시 폴더에서 만들어 사라짐),
  새 주소라 카톡 미리보기는 어차피 새로 뜬다.
- 봇 메시지의 링크 교체는 사용자가 카톡에서 직접 한다.

## 4. 빼는 것

| 기능 | 화면에서 | 코드 | 서버 데이터 |
|---|---|---|---|
| 방명록 | 선수 상세 아래 칸, 라커룸에 걸린 곳 | `Guestbook.tsx` 와 연결 지운다 | `guestbook` 표·함수는 그대로 둔다 |
| POTM | 매치 카드 [POTM 투표], 선수 카드·라커룸의 POTM 표시, `/matches/potm/` | `PotmApp.tsx` 등 지운다. `/matches/potm/` 은 `/matches/` 로 넘김 페이지 | `potm_votes`·`potm_awards` 그대로 |
| 벌금 기록 | 이미 화면에 없음 | `fines` 정규화·`writeFine`/`deleteFine`·`unpaidRows` 등 안 쓰는 연결 | `fines` 표 그대로 |

- **남기는 것**: 규칙 페이지 「비용 · 벌금」의 `FineRulesTable`·면제 문구·사용처 문장(사용자 결정 — 제도는 그대로다).
- 서버(Supabase) 표·함수는 이번에 건드리지 않는다. 되돌릴 여지를 남기려는 것(내 결정). 마이그레이션 없음.
- `og-potm.png` 처럼 POTM 전용 정적 파일도 지운다.
- **지난 기록의 표시도 화면에서 뺀다(내 결정)**: 매치 카드의 지난 POTM 결과 줄·[POTM 이미지] 버튼, 관리자 통계의 방명록·POTM 열,
  이름 고르기 확인 문구 속 "방명록".
- **예외 하나**: `StatHistory.tsx` 의 `via === 'potm'` → 「POTM 보상」 표기는 남긴다. 지우면 지난 보상 줄이 「직접 고침」으로 잘못 읽힌다.
- **라커룸**: `.rail` 은 3×3 고정 격자라 「최근 방명록」 칸이 빠지면 구멍이 난다. 그 자리에 「처음 왔다면」 칸(`/guide/` 링크)을 넣는다(내 결정).
- 서버의 `settle_potm` 예약 작업은 그대로 둔다. 새 표가 없으면 아무 일도 하지 않는다.

## 6. 확인

- `npm run build` 통과, 지운 기능 이름(guestbook·potm·writeFine)이 `src/` 에 남지 않음(넘김 페이지와 StatHistory 의 표기 분기 제외).
- 테스트를 함께 고친다: `tests/build/dist.test.mjs`(메뉴 여덟 개·`og-potm.png` 단언), matches·card 단위 테스트. 고친 뒤 전부 통과.
- 로컬에서 390px·1280px로 메뉴 6개·하위 탭 전환·활성 표시를 눌러서 확인.
- `/guide/` 버튼이 로그인 창을 여는지, 로그인한 상태의 문구가 바뀌는지 클릭으로 확인(가짜 로그인 상태로 UI만, 실서버 claim 은 실사용이 검증).
- 옛 주소 `/matches/potm/?m=…`·`/rules/`·`/kit/`·`/lineup/` 이 살아 있는지.
